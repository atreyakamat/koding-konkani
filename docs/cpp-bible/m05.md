### Narration script

**\[1 · Title\]** Today we look under the hood. Every variable lives at an address in memory. Soon you will use that address.

**\[2 · Memory and addresses\]** Memory is a long row of bytes. Each byte has a number, called its address. A variable lives at one address, and it fills as many bytes as its type needs.

The ampersand in front of a variable gives its address. Think of a street of houses. Each house has a number, and a family lives inside.

Why should a beginner care about addresses? Because the most powerful tools in C plus plus work with them. Pointers, arrays and the heap all depend on this idea.

Addresses are long numbers, and we usually write them in a base that uses letters too. You do not need to read them. You only need to know that each variable has one, and that no two variables share the same bytes.

**\[3 · The gap between boxes\]** \[HL 5\] An array of three ints. \[HL 6\] The ampersand gives the address of the first item. We view it as a char address, so that we can count bytes. \[HL 7\] This is the address of the second item.

\[HL 8\] The difference is four bytes. That is the size of one int. The real addresses change from run to run, but the gap is always four. \[HL 5\] Three ints sit side by side in memory.

\[HL 6\] The ampersand gives the address of the first item. We turn it into a char pointer, so we can count in single bytes. \[HL 7\] The same trick gives the address of the second item. \[HL 8\] The difference is four.

An int takes four bytes, so the next item starts four bytes later.

**\[4 · Addresses in a row\]** Look at the three boxes. The first sits at address one thousand. The next sits at one thousand and four. The last at one thousand and eight.

These addresses are examples. On a real computer, the numbers differ every time you run the program. Notice that every box has an address, a size and a value. The address says where it starts.

The size says where it ends. The value is what the bytes mean for that type.

**\[5 · Sizes decide the gap\]** \[HL 5\] A char takes one byte. \[HL 6\] An int takes four. \[HL 7\] A double takes eight. \[HL 8\] An address itself takes eight bytes on a sixty-four-bit computer.

Remember this. We will store addresses in variables soon. \[HL 5\] A char takes one byte. \[HL 6\] An int takes four bytes on most machines.

\[HL 7\] A double takes eight. \[HL 8\] A pointer to an int is also a fixed size. On a modern computer with sixty-four bits, it takes eight bytes. Every pointer has the same size, whatever it points to.

**\[6 · Run it\]** Save the file as sizes dot cpp. Compile it with g plus plus. Then run the program.

The program prints one, four, eight and eight on four lines. Notice that the size of a pointer does not depend on the type behind it. An int star and a double star are both eight.

**\[7 · Recap\]** Let us recap.

Three. The ampersand gives the address of a variable. Four. An address is not the same as a value.

**\[8 · Storing an address in an int\]** Bug of the Day. We store the address of fish in a plain int. The compiler says invalid conversion from int star to int. An address has its own type.

For the address of an int, that type is int star. We learn it in the next episode. An address is not a number that you can store in an int. It has its own type, and the type remembers what lives at that address.

### Bug of the Day

**Bug kind:** compile · **Bug file:** addr.cpp

Wrong code (an address goes into a plain int):

```cpp
#include <iostream>
using namespace std;

int main() {
    int fish = 3;
    int where = &fish;
    cout << where << endl;
    return 0;
}
```

Compiler output (exactly as g++ prints it):

```text
addr.cpp: In function 'int main()':
addr.cpp:6:17: error: invalid conversion from 'int*' to 'int' [-fpermissive]
    6 |     int where = &fish;
      |                 ^~~~~
      |                 |
      |                 int*
```

Fixed code (a pointer type holds the address):

```cpp
#include <iostream>
using namespace std;

int main() {
    int fish = 3;
    int* where = &fish;
    cout << (where != nullptr) << endl;
    return 0;
}
```

**Fixed output:**

```text
1
```

**Why:** An address has its own type. For an int, the type is int star. A plain int cannot hold it.

### Bug of the Day

**Bug kind:** compile · **Bug file:** pointer.cpp

Wrong code (an int pointer holds the address of a double):

```cpp
#include <iostream>
```

```text
pointer.cpp: In function 'int main()':

      |              ^~~~~~
      |              |
      |              double*
```

Fixed code (the pointer type matches):

```cpp

    double price = 1.5;
    double* p = &price;
    cout << *p << endl;
    return 0;
}
```

**Fixed output:**

```text
1.5
```

**Why:** The type of a pointer says how to read the bytes at the address. A pointer to int cannot point at a double.

```text
count.cpp:4:21: note: declared here
    4 | int count_items(int a[]) {
```

Fixed code (the size is passed in):

```cpp
#include <iostream>
using namespace std;

int count_items(const int a[], int n) {
    int count = 0;
    for (int i = 0; i < n; i++) {
        count += a[i] > 0 ? 1 : 0;
    }
    return count;
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    cout << count_items(a, 5) << endl;
    return 0;
}
```

**Fixed output:**

```text
5
```

**\[1 · Title\]** Today we do maths with addresses. The rules are simple, but they surprise most beginners.

**\[2 · Pointer arithmetic\]** When you add one to a pointer, it moves by one item, not by one byte. For an int pointer, the address grows by four. For a double pointer, it grows by eight.

You may subtract two pointers into the same array. You get the number of items between them. You may not add two pointers. Think of a bus conductor. One stop forward means one seat, not one metre.

Pointer arithmetic is a big help, because the compiler does the byte counting for you. You think in items, and it works in bytes.

The rules are strict. You may add a number to a pointer, subtract a number, or subtract two pointers. You may not add two pointers, multiply them or divide them. Those have no meaning.

**\[3 · Hop by one item\]** \[HL 6\] P points to the first item. \[HL 7\] Q is p plus one. It points to the second item. \[HL 8\] It reads six.

**\[4 · One step is one item\]** Look at the table. P plus one moves one item. For an int pointer that is four bytes.

For a double pointer it is eight bytes. The compiler does the multiplication for you. Subtracting two pointers gives a count of items, not bytes.

Notice the two columns in the table. One column counts items, and the other counts bytes. The same step is one item for the compiler, and four bytes for the machine.

```cpp
#include <iostream>
```

```text
      |                 int*  int*
```

Fixed code (the middle is low plus half the distance):

```cpp
#include <iostream>
using namespace std;

int main() {
```

```text
3
```

### Narration script

**\[1 · Title\]** Today we stop leaks for good. The trick is simple. Let a variable do the cleaning when it dies.

**\[2 · Leaks and RAII\]** A memory leak happens when you lose the address of a heap box before you free it. An early return or an error can cause it.

The cure is RAII. It means that a resource belongs to a variable. When the variable dies, a special function called the destructor runs, and it frees the resource. Think of a hotel room. It cleans itself when you check out.

RAII is a long name for a simple idea. Let a variable own the resource. When the variable goes away, the resource goes with it.

The compiler runs the destructor for you at the closing brace. This holds on every exit path. That includes an early return and an error.

**\[3 · A destructor runs\]** \[HL 4\] This struct has two special functions. We study them in module six. \[HL 5\] The first runs when a Noisy is made. \[HL 6\] The second, with a tilde, runs when it dies.

\[HL 11\] Here a Noisy is made, and open prints. \[HL 12\] Then working prints. \[HL 14\] The block ends, so n dies and close prints before the next line. \[HL 5\] The constructor runs when the object is made.

It prints open. \[HL 6\] The destructor has a tilde in front of its name. It runs when the object dies, and it prints close. \[HL 11\] The object n is made here.

\[HL 12\] The message working appears. \[HL 13\] At the closing brace, the destructor runs by itself, before the line after the block.

**\[4 · The life of a variable\]** Follow the life of n. It is made, and open prints. The block uses it. At the closing brace, n goes out of scope.

The destructor runs at once, and close prints. You did not write any cleanup call. Notice the order. Open comes first, then working, then close.

The close appears at the closing brace, with no call from us. The compiler writes that call for us, every time.

**\[5 · A leak by early return\]** \[HL 10\] This function makes a Noisy on the heap with new. \[HL 11\] If fail is true, the function returns early. \[HL 14\] The delete is skipped. \[HL 18\] The first call prints open and close.

\[HL 19\] The second call prints open only. The close is missing. That box is leaked. \[HL 10\] This line makes a Noisy object on the heap, with new.

\[HL 11\] When fail is true, the function returns early. \[HL 14\] The delete is skipped, so the destructor never runs. The first call prints open and close. The second call prints open only.

### Narration script

**\[1 · Title\]** Today we meet the smart pointer that you will use most. It owns a heap object, and it frees the object for you.

**\[2 · unique_ptr\]** A unique pointer owns one heap object. When the unique pointer dies, it deletes the object. You never write delete. This is RAII for heap memory.

A unique pointer has one owner. You cannot copy it, but you can move it to a new owner. Think of a house key with one owner. You can hand it over, but you cannot copy it.

Modern C plus plus advises you to avoid raw new and delete. Smart pointers do the work. Unique pointer is the first choice.

It costs nothing extra. It is as fast as a raw pointer, and it deletes the object at the right time.

**\[3 · make_unique\]** \[HL 2\] The memory header holds the smart pointers. \[HL 6\] Make unique builds an int with the value five on the heap. The unique pointer p owns it. \[HL 7\] Star works as before.

It reads five. \[HL 8\] We change it to eight. \[HL 10\] At the end of main, p dies and deletes the int. There is no delete in our code.

\[HL 6\] Make unique builds the int on the heap, and the unique pointer owns it. \[HL 7\] The star works as with a raw pointer. We see five. \[HL 8\] We can change the value, as before.

\[HL 10\] When main ends, the unique pointer dies, and the heap box is freed. We wrote no delete.

**\[4 · One owner\]** Look at the arrow. P owns the int on the heap. There is only one owner. When p goes out of scope, it deletes the int.

A raw pointer has no such duty. It only points. Notice the single owner. The key has one holder.

If you hand the key to someone else, you no longer have it. This rule makes double delete impossible.

**\[5 · Move the ownership\]** \[HL 7\] A owns an int with the value five. \[HL 8\] Move hands the ownership to b. \[HL 9\] A is now empty. It equals nullptr, so the program prints one.

\[HL 10\] B owns the int and reads five. When b dies, the int is deleted exactly once. \[HL 8\] The move function hands the object from a to b. After that, a is empty.

\[HL 9\] A moved-from pointer equals nullptr, so the test prints one. \[HL 10\] The new owner b still sees the value five.

```cpp
#include <iostream>
```

```cpp
#include <utility>
```

**Fixed output:**

```text
5
```

### Narration script

**\[1 · Title\]** Today the ownership is shared. Many pointers own one object, and the last one to leave switches off the light.

**\[2 · shared_ptr and weak_ptr\]** A shared pointer lets many owners share one object. A counter inside tracks the owners. When the last owner dies, the object is deleted.

A weak pointer looks at the object but does not own it. It does not change the counter. Think of a Wi-Fi password. Many people share it, and the router stays on until the last person leaves.

Some objects have many owners. A shared pointer fits. It keeps a counter, and it deletes the object when the counter reaches zero.

Weak pointer solves a problem. If two objects own each other with shared pointers, neither is ever freed. A weak pointer breaks the circle, because it does not own.

**\[3 · Count the owners\]** \[HL 6\] Make shared builds an int and one shared pointer. \[HL 7\] The count is one. \[HL 9\] B is a copy. Copying is allowed here.

Both own the int. \[HL 10\] The count is two. \[HL 11\] At the closing brace, b dies. \[HL 12\] The count drops back to one.

\[HL 6\] Make shared builds the object, and the count is one. \[HL 7\] The use count call reads the count. It prints one. \[HL 9\] Another shared pointer copies a, so the count grows to two.

\[HL 12\] The inner block ends, b dies, and the count falls back to one.

**\[4 · Two owners, one object\]** Here are two owners, a and b. Both point at the same int. A counter next to the int says two. When b dies, the counter becomes one.

When a dies, it becomes zero, and the int is deleted. Notice the counter in the middle of the picture. Every new owner adds one, and every owner that leaves takes one away. At zero, the object is freed.

**\[5 · A weak pointer\]** \[HL 6\] W is a weak pointer. It owns nothing. \[HL 8\] S owns an int with the value seven. \[HL 9\] W now watches the same object.

\[HL 10\] Expired asks if the object is gone. Not yet, so zero. \[HL 11\] Lock gives a shared pointer, if the object is alive. \[HL 12\] It reads seven.

\[HL 15\] After the block, s is dead. The object is deleted, and expired is one. \[HL 6\] The weak pointer starts empty. \[HL 9\] It watches the object, but the count stays the same.

\[HL 11\] Lock gives a shared pointer if the object is alive. If not, it gives an empty pointer. \[HL 15\] After the block, the object is gone, so expired is true.

**\[6 · Run it\]** Save the file as weak dot cpp. Compile it with g plus plus. Then run the program. The program prints zero, seven, and then one.

Notice the order. The first expired call gives false. The second one gives true, after the object died.

**\[7 · Recap\]** Let us recap.

One. Many shared pointers can own one object. Two. A counter tracks the owners, and the last owner deletes the object.

Three. A weak pointer watches without owning. Four. Lock turns a weak pointer into a shared pointer, or an empty one.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · A raw pointer into a shared_ptr\]** Bug of the Day. We assign a raw new result to a shared pointer. The compiler says it cannot convert int star to shared pointer.

Use make shared instead. It builds the object and the counter in one safe step. The constructor of a shared pointer is explicit, so the equals sign does not work.

Do not wrap a raw pointer by hand. Use make shared. It is shorter, it is safe, and it does one memory request instead of two.

**\[9 · Pun\]** Shared pointers are polite. The last one out always turns off the light.

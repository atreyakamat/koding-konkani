### Narration script

**\[1 · Title\]** Today you write your first C plus plus program. It has only five lines. At the end, your computer says hello to Goa.

**\[2 · Hello, C++!\]** C plus plus is a programming language. You write instructions in a text file. The computer cannot read that file directly.

A tool called a compiler changes your text into a program. Then the computer can run it. Games, web browsers and phone apps use C plus plus. Think of a recipe. You write the steps, and the cook follows them.

Why does the computer need a compiler? A processor understands only tiny steps made of ones and zeros. Your text is easy for you to read, but it is hard for the processor. The compiler is the translator between the two.

Bjarne Stroustrup created C plus plus. He started in nineteen seventy-nine and gave it the name in nineteen eighty-three. The language still grows, and a new version arrives about every three years. Banks, games, cars and rockets run on C plus plus code.

**\[3 · Your first program\]** \[HL 1\] This line adds the iostream header. It gives us cout, the tool that prints text. \[HL 3\] Every program has a function called main. The computer starts here.

\[HL 4\] This line prints the words Namaskar, Goa. Text goes inside double quotes. The word endl ends the line. \[HL 5\] Return zero tells the computer that all is well.

\[HL 6\] The closing brace ends main. \[HL 1\] Think of the include line as a loan from a library. Without it, the computer does not know the word cout. \[HL 3\] The word int before main means that the function gives back a whole number when it ends.

\[HL 4\] Look at the arrows. They point from the text toward cout, as if you push the words onto the screen. Double quotes hold the text exactly as you type it, so every space and every letter counts. \[HL 5\] The value zero is a polite message to the operating system.

Any other number tells it that something went wrong.

**\[4 · Write, compile, run\]** Here is the full journey. First, you write the code in a text file. Second, the compiler turns the text into a program. Third, you run the program, and the words appear on the screen.

You repeat these three steps in every episode. Notice that most mistakes appear in the compile step. The compiler checks every line before it builds the program. If it finds a mistake, it stops and tells you which line to fix.

The run step is quick, because the program is already built. Remember the order. Write, compile, run.

**\[5 · Two lines\]** \[HL 4\] The first cout prints a line about you. \[HL 5\] The second cout prints our sign-off. The computer runs the lines in order, from top to bottom.

\[HL 6\] Then main returns zero and the program ends. \[HL 4\] Each cout line is one statement, and each statement ends with a semicolon. \[HL 5\] Order matters here.

If you swap these two lines, the sign-off prints first. Try it yourself after the video. Swap the lines, compile again, and watch the output change.

**\[6 · Run it\]** Save the file as twolines dot cpp. Compile it with g plus plus. Then run the program. The two lines appear, one under the other. Each endl moves the cursor to the next line, so the two messages do not join together.

**\[7 · Recap\]** Let us recap.

One. C plus plus is a language that you compile. Two. Every program starts in a function called main.

Three. The tool cout prints text to the screen. Four. You write, compile and run, in that order.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · A missing semicolon\]** Bug of the Day. Here the cout line has no semicolon at the end. The compiler stops and shows an error. It says expected semicolon before return.

Every statement in C plus plus must end with a semicolon. Add it, and the program builds. Here is a tip for reading errors. Read the message from the top.

The first line names the file and the line number. The compiler often points to the line after the real mistake. It notices the problem only when the next statement starts. So when you see an error, look at the line above it too.

**\[9 · Pun\]** I told my compiler a joke. It said, I do not get it. Expected semicolon.

### Bug of the Day

**Bug kind:** compile · **Bug file:** hello.cpp

Wrong code (the cout line has no semicolon):

```cpp
#include <iostream>

int main() {
    std::cout << "Namaskar, Goa!" << std::endl
    return 0;
}
```

Compiler output (exactly as g++ prints it):

```text
hello.cpp: In function 'int main()':
hello.cpp:4:47: error: expected ';' before 'return'
    4 |     std::cout << "Namaskar, Goa!" << std::endl
      |                                               ^
      |                                               ;
    5 |     return 0;
```

Fixed code (the semicolon is back):

```cpp
#include <iostream>

int main() {
    std::cout << "Namaskar, Goa!" << std::endl;
    return 0;
}
```

**Fixed output:**

```text
Namaskar, Goa!
```

**Why:** A semicolon ends a statement. Without it, the compiler cannot see where one instruction stops.

**\[2 · Setting up and compiling\]** You need three tools. The editor is where you type your code. We use Visual Studio Code.

The compiler builds your program. We use g plus plus, from the GCC family. The terminal is where you type commands and run programs. Think of a kitchen.

The editor is the notebook with the recipe. The compiler is the stove. The terminal is the table where you eat.

Here is how the three tools work together. First, you open the editor and type your code. Then you save the file with the dot cpp ending. Next, you open the terminal in the same folder. There you run the compiler on your file.

If the compiler finds no mistakes, it creates a program. Then you run that program from the terminal. On Windows, we get the compiler from M S Y S two. Linux users often have g plus plus ready already.

**\[3 · A setup check\]** Type this program in your editor and save it as setup dot cpp. \[HL 4\] The first line of main reports on the editor. \[HL 5\] The second line reports on the compiler. \[HL 6\] The third line reports on the terminal.

If you see all three lines at the end, your setup works. \[HL 4\] Notice that all three lines look the same. Only the words inside the quotes change. \[HL 5\] This is the pattern of a first program.

You write one statement for each message. \[HL 6\] If a line is missing in your output, check the semicolon and the closing quote. \[HL 7\] The return line stays at the end of main.

**\[4 · Three tools\]** Look at the table. The editor lets you type and save code. The compiler reads your file and builds a program. The terminal lets you type the compile command and run the result.

Every episode uses all three. Pick one editor and stay with it for the whole course. Visual Studio Code is free, and it works on Windows, Mac and Linux. The terminal must know where the compiler lives on your computer.

If the terminal says command not found, this is the usual reason. Close the terminal, open it again, and try once more.

**\[5 · Which C++ version?\]** \[HL 4\] A built-in name holds a number for the language version. The name starts with two underscores, then c plus plus. With the flag std equals c plus plus twenty, the number is two zero two zero zero two.

That number means C plus plus twenty. We use this version in the whole course. The compiler fills in this number by itself.

You never type it. Each language version has its own code, so you can always check which version the compiler uses. If you forget the flag, the compiler may use a different version, and some new features will not work.

**\[6 · Run it\]** Save the file as standard dot cpp. Compile it with g plus plus. Then run the program.

Three. The flag dash Wall shows helpful warnings. Four. Always compile again after you change the code.

Pause the video. Say these ideas out loud, one time, slowly.

### Narration script

**\[1 · Title\]** Today we compare C and C plus plus. You will see what stayed the same, and what is new.

**\[2 · C vs C++: what changed\]** C plus plus grew out of the C language. Most C code still works in C plus plus. But C plus plus adds many features. It has classes, a bigger library, and safer ways to handle memory.

Think of a bicycle and a motorbike. Both carry you to school. The motorbike has more parts, so you must learn more.

Bjarne Stroustrup built C plus plus on top of C, because C is fast. He wanted to keep that speed and add tools for big programs. That is why a lot of old C code still compiles in C plus plus.

But C plus plus is not only C with extra parts. It has its own style, and good C plus plus code looks different from C code. In this episode, we compare the two styles side by side.

**\[3 · The C way\]** \[HL 1\] The header cstdio gives us printf, the C way to print. \[HL 4\] Printf works in C plus plus too. The backslash n at the end starts a new line. Notice the prefix std colon colon.

C plus plus keeps its library names inside the std namespace. \[HL 1\] The name cstdio starts with the letter c. In C plus plus, a header from C gets a c in front. It also loses the dot h.

\[HL 4\] The printf function needs a format string. Here, the format string is plain text with a new line at the end. \[HL 5\] Nothing else changes in main. This is why many C programs still run as C plus plus.

**\[4 · C and C++ side by side\]** Here are five differences. For printing, C uses printf, and C plus plus uses cout. For reading, C uses scanf, and C plus plus uses cin. For text, C uses char arrays, and C plus plus has std string.

For memory, C plus plus gives you smart pointers. For grouping data, C plus plus has classes. We will learn each one. Do not worry if the table feels long.

You do not need to learn it by heart now. Each row gets its own episode. For now, remember the big idea. C plus plus gives you safer and shorter ways to do the same jobs.

You can still use the C way when you need it.

**\[5 · The C++ way\]** \[HL 4\] Now the C plus plus way. The cout tool takes the text with the insertion operator, which looks like two arrows. The endl word ends the line.

\[HL 5\] The program returns zero, as before. Both styles give the same result on the screen. \[HL 1\] This time, we include iostream instead of cstdio.

\[HL 4\] Cout does not need a format string. You push the text into it with the arrows, and you can add more pieces with more arrows. Later, we chain values this way, and you will see why it is handy.

**\[6 · Run it\]** Save the file as cppstyle dot cpp. Compile it with g plus plus. Then run the program. Both programs print one hello line.

C plus plus lets you choose either style. The C style and the C plus plus style print the same text. The difference is in how you write it.

**\[7 · Recap\]** Let us recap.

One. C plus plus grew out of C. Two. Printf is the C way, and cout is the C plus plus way.

Three. Library names live in the std namespace. Four. C plus plus adds classes, strings and smart pointers.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · Forgetting std\]** Bug of the Day. Here we write cout without std in front. The compiler says cout was not declared in this scope. It also suggests std colon colon cout.

Library names live in the std namespace. Add the prefix, and the error goes away. The name cout lives inside std. The compiler looks in the global space first, and it finds nothing.

Many beginners meet this error in the first week, so do not worry. The fix is a small prefix. You will type std colon colon many times, and soon it feels natural.

### Narration script

**\[1 · Title\]** Today we cut a program into parts, like a fish on a plate. You will name every part.

**\[2 · Anatomy of a C++ program\]** Every C plus plus program has the same parts. A comment is a note for people. The compiler ignores it.

An include line brings in library tools. The main function is where the program starts. Statements do the work, and each ends with a semicolon. Think of a thali. Each dish has its own spot on the plate.

Let us look at each part in more detail. Comments help you and other people read the code later. Good programmers write comments that explain why, not what.

The include line asks the compiler to read a library first. The main function is the front door of the program. The statements inside it run in order, from top to bottom. The close brace is the last piece.

**\[3 · Name the parts\]** \[HL 1\] The two slashes start a comment. The compiler skips it. \[HL 2\] The include line brings in iostream. \[HL 4\] The main function starts here, and the open brace starts its body.

\[HL 5\] This statement prints a line. A comment can also sit at the end of a line. \[HL 6\] The return statement ends the program. \[HL 7\] The close brace ends main.

\[HL 1\] A comment can say who wrote the program or what it does. \[HL 5\] The comment at the end of this line explains the statement. Use comments with care. Too many comments make code harder to read.

\[HL 6\] The return statement is optional in main, but we write it so the ending is clear. \[HL 7\] Always match every open brace with a close brace.

**\[4 · The parts in order\]** Here are the parts in order. First, the comment. Second, the include line. Third, the main function.

Inside main, the statements do the work. At the end, return sends zero back to the computer. Every program you write follows this shape. Notice the order from top to bottom.

A comment can go anywhere, but the include line must come before the code that uses it. The main function holds the statements. Return is the last statement. If you keep this order, your programs stay easy to read.

**\[5 · A using line\]** \[HL 2\] This using line tells the compiler to look inside std. \[HL 5\] Now we can write cout and endl without the prefix. The program is shorter. In big projects, the prefix is safer, so we use both styles in this course.

\[HL 6\] The return statement is the same as before. \[HL 2\] A using line saves typing in small programs. But two libraries can use the same name for different things. Then the compiler cannot tell which one you mean.

That is why big projects keep the std prefix. \[HL 5\] For now, both styles are fine.

**\[6 · Run it\]** Save the file as shortnames dot cpp. Compile it with g plus plus. Then run the program.

The program prints one line. The output is the same as with std colon colon. The compiler treats both styles in the same way, so choose the one that is clear to you.

**\[7 · Recap\]** Let us recap.

One. A comment is a note for people. Two. The include line brings in library tools.

Three. Main is where the program starts. Four. A using line lets you drop the std prefix.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · A missing closing brace\]** Bug of the Day. Here the closing brace of main is missing. The compiler reads to the end of the file. Then it says expected close brace at end of input.

Every open brace needs a close brace. Add it, and the program builds. Braces come in pairs, like the two covers of a book. When a close brace is missing, the compiler keeps reading until the file ends.

Then it complains about the end of input. If you see that message, count your braces. Many editors highlight the matching brace when you click on one, and that helps a lot.

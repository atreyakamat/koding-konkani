### Narration script

**\[1 · Title\]** Reading is only half the story. Today we write data to a file, and learn which mode to pick.

**\[2 · Three modes\]** Open takes a second argument, the mode. R is read, the default. W is write. It creates the file if needed, and wipes whatever was there. A is append. It adds to the end and keeps what was there. Think of a diary. Write mode tears out all the pages and starts fresh. Append mode adds a new page at the end. Write puts text in with the write method. It does not add new lines for you.

**\[3 · Write mode\]** \[HL 1\] Open log dot txt in write mode. If the file is missing, Python creates it. \[HL 2\] Write a line. The slash n at the end is a new line character. Write does not add one for us. \[HL 3\] Another line. \[HL 4\] Close the file. This saves everything to disk. \[HL 5\] Read it back and print. Day one, Day two. The extra blank line is the final new line.

**\[4 · Write versus append\]** Here is the difference, in pictures. A diary with three pages. Open it in write mode, and every old page is torn out, before you write a single word. Open it in append mode, and the old pages stay, and your new text goes after them. Write is for starting over. Append is for adding. Pick carefully.

**\[5 · Append mode\]** \[HL 1\] Open the existing log in append mode. \[HL 2\] Write one more line. It goes after the lines that are already there. \[HL 3\] Close. \[HL 4\] Read the file back, and count the word Day. Three. All three days are there. The earlier lines survived, because append never wipes.

**\[6 · Run it\]** Save the file as append dot py. In the terminal, type python, space, append dot py. Three.

**\[7 · Recap\]** Let us recap. One: Mode r reads, w writes and wipes, a appends. Two: write does not add a new line for you. Three: Close the file so the data is saved. Four: Use a to add to a file and keep what is there. Pause the video, and say these ideas out loud, once, slowly.

### Narration script

**\[1 · Title\]** Forgetting to close a file is a classic mistake. Today we learn a form that cannot forget.

**\[2 · Files that close themselves\]** The with statement opens a file, and closes it for you when the block ends. Think of an automatic door. It closes behind you, even if you forget. Write with open, the name, as f, and a colon. The indented block can use f. When the block ends, even through an error, Python closes the file. Closing matters. Text that you write can stay in a buffer. It reaches the disk only when the file is closed.

**\[3 · with and read\]** \[HL 1\] The with line. Open the file, and tie it to f, for the block. \[HL 2\] Inside the block, read the text. \[HL 3\] The block has ended, so Python has already closed the file. We use the text we saved. Capital letters. \[HL 4\] The closed attribute confirms it. True. We never wrote close ourselves.

**\[4 · Open, use, auto-close\]** Here is the timeline. The with line opens the file. The block runs. When the block ends, the file is closed. Now imagine an error in the middle of the block. Without with, the close line does not run. With with, Python still closes the file on the way out. That is why with is the standard way to work with files.

**\[5 · with and write\]** \[HL 1\] Open for writing, inside with. \[HL 2\] Write one line. When this block ends, the file is closed and saved. \[HL 3\] Open the same file for reading, in a new with. \[HL 4\] Read it, strip the new line, and print. Hello. Two with blocks, and no close in sight.

**\[6 · Run it\]** Save the file as withwrite dot py. In the terminal, type python, space, withwrite dot py. Hello.

**\[7 · Recap\]** Let us recap. One: with open of ... as f: closes the file when the block ends. Two: It closes even when an error happens inside.

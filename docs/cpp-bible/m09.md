### Narration script

**\[1 · Title\]** Today we stop writing loops by hand. The standard library already has tools for sorting, searching and counting.

**\[2 · Algorithms from the library\]** The algorithm header holds many ready tools. Each tool takes a range, which is a begin iterator and an end iterator.

The tools are tested and fast. Think of a toolbox. You pick the tool, and you do not build it again.

Experienced programmers rarely write a loop for sorting, searching or counting. They call an algorithm. The code is shorter, and it has fewer bugs.

The library algorithms are tuned by experts. Most of the time, they are faster than what you would write yourself. Learn the names, and you will save hours.

**\[3 · Sort, max and reverse\]** \[HL 8\] Sort takes the begin and the end of the vector. It puts the numbers in order. \[HL 9\] The loop prints one two five seven nine. \[HL 13\] Max element returns an iterator to the biggest value.

\[HL 13\] The star reads the value, which is nine. \[HL 14\] Reverse flips the order. \[HL 15\] The first item is now nine. \[HL 8\] Sort takes two iterators, the start and the end.

After this line, the vector is in order. \[HL 13\] Max element gives an iterator, so we put a star in front to read the value. The answer is nine. \[HL 14\] Reverse turns the order round.

\[HL 15\] Now the first item is nine.

**\[4 · Common algorithms\]** Here are five tools. Sort, find, count and reverse live in the algorithm header. Accumulate lives in the numeric header. All five take a range.

Notice the common shape of the calls. Each takes a begin and an end. Then it may take a value or a rule. Once you know one algorithm, the others feel familiar.

**\[5 · Find, count and accumulate\]** \[HL 9\] Find returns an iterator to the first match. \[HL 10\] If the result is not the end, the value exists. \[HL 11\] Subtracting the begin gives the index, which is one. \[HL 13\] Count returns how many fours there are, which is three.

\[HL 14\] Accumulate adds all values, starting from zero. The sum is twenty-one. \[HL 9\] Find looks for the value eight, and it gives an iterator. \[HL 10\] Always test the iterator against end, before you read it.

\[HL 13\] Count tells how many times four appears. It is three. \[HL 14\] Accumulate adds all the items, starting from zero. The total is twenty-one.

**\[6 · Run it\]** Save the file as find dot cpp. Compile it with g plus plus. Then run the program.

The program prints found at one, then three, then twenty-one. Check by hand. Four plus eight plus four plus one plus four is twenty-one.

**\[7 · Recap\]** Let us recap.

One. Algorithms work on a range of iterators. Two. Sort puts a range in order.

Three. Find returns an iterator, and the end means not found. Four. Accumulate adds up a range.

**\[8 · Sort with no iterators\]** Bug of the Day. We call sort with only the vector. The compiler says there is no matching function.

Sort needs a begin and an end. Pass both iterators. The classic sort needs the start and the end.

If you pass only the vector, the compiler cannot match the call. C plus plus twenty has a ranges version that takes the whole vector. For now, write begin and end.

### Narration script

**\[1 · Title\]** Today we hand rules to algorithms. A lambda is a small function you write in the same place where you use it.

**\[2 · Lambdas with algorithms\]** A lambda has square brackets, a parameter list and a body. The square brackets are the capture list. They name outside variables that the lambda may read.

Think of a sticky note with a small rule. You hand the note to the algorithm, and it follows the rule.

Many algorithms take a rule as the last argument. The rule says how to compare, or what to count. A lambda is the best way to write the rule.

Write the lambda right where you need it. The reader sees the rule next to the call, and does not have to jump to another place.

**\[3 · Sort descending and count_if\]** \[HL 8\] The empty square brackets mean the lambda captures nothing. It takes two ints. \[HL 8\] It says that a comes first when a is bigger. The result is nine seven five two one.

\[HL 13\] Now we make a local variable. \[HL 14\] Putting limit in the brackets captures it. The lambda can now read it. \[HL 14\] Count if counts the items for which the lambda says true.

Three items are bigger than four. \[HL 8\] The third argument is a lambda that takes two ints. It returns true when a is bigger than b. This changes sort from smallest first to biggest first.

\[HL 13\] The variable limit is four. \[HL 14\] The capture list holds limit, so the lambda can read it. Count if counts the numbers above four. The answer is three.

**\[4 · Anatomy of a lambda\]** A lambda has three parts. The capture list names outside variables. The parameters are the values the algorithm passes in. The body holds the rule.

Notice the two jobs. The lambda in sort decides the order of two items. The lambda in count if answers a yes or no question about one item. The algorithm calls the lambda again and again.

**\[5 · Sort a struct by marks\]** \[HL 7\] A student has a name and marks. \[HL 14\] We sort the students. \[HL 14\] The lambda compares marks, so the highest marks come first.

\[HL 15\] For each calls a lambda on every item. \[HL 15\] The lambda prints Asha ninety-one, then Mia eighty-five, then Ravi seventy-eight. \[HL 13\] This vector holds three students.

\[HL 14\] The lambda compares the marks, so the students are ordered by their marks, highest first. \[HL 15\] For each runs a lambda on every student. It prints the name and the marks.

**\[6 · Run it\]** Save the file as students dot cpp. Compile it with g plus plus. Then run the program.

The program prints the three students, from the highest marks to the lowest. Notice the order of the output. Asha has ninety-one, Mia has eighty-five, and Ravi has seventy-eight.

**\[7 · Recap\]** Let us recap.

One. A lambda is a small function with no name. Two. The capture list names outside variables.

Three. Algorithms take lambdas as rules. Four. Pass a struct by const reference to avoid a copy.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · A variable that is not captured\]** Bug of the Day. The lambda reads limit, but the brackets are empty. The compiler says limit is not captured. Put limit in the square brackets.

A lambda starts with a clean slate. It sees nothing from outside until you capture it. Write the name in the square brackets to copy it. Add an ampersand to use the original variable, and to change it.

### Narration script

**\[1 · Title\]** Until now, one student meant a name in one list and marks in another. Today we bundle them together.

**\[2 · One thing, one bundle\]** Imagine you track students. One list holds the names. Another list holds the marks. They line up only by position. Move one item, and everything goes wrong. A class fixes this. It is a blueprint for one type of thing. It says what data each thing carries, and what it can do. An object is one real thing built from the blueprint. Think of a student file. Name, marks and class live in one folder, so they can never get separated.

**\[3 · Parallel lists\]** \[HL 1\] One list of names. \[HL 2\] Another list of marks. The two lists match only by position. \[HL 3\] We loop with an index. \[HL 4\] And print both lists at the same position. Asha ninety one, Ravi seventy eight, Meera eighty five. \[HL 5\] Find the position of the best mark. \[HL 6\] And look up the name at that position. Asha. It works, but only while the two lists stay perfectly in step.

**\[4 · Two cupboards, one student\]** Here is the problem. The name of Asha sits in one cupboard. Her marks sit in another. If you sort one cupboard, or delete from one, the match breaks, and Asha gets Ravi's marks. A class puts both into one folder. When you move the folder, everything inside moves together. That is the whole idea of bundling.

**\[5 · A first tiny class\]** \[HL 1\] The word class starts a blueprint. The name is Student, with a capital letter. \[HL 2\] Pass means, nothing inside yet. \[HL 4\] Student with brackets builds one object, tied to a. \[HL 5\] We give it a name. \[HL 6\] And marks. \[HL 7\] A second student, tied to b. \[HL 8\] With its own name. \[HL 9\] And its own marks. \[HL 10\] Each object keeps its own data. Asha ninety one. \[HL 11\] Ravi seventy eight. Next episodes make this tidier.

**\[6 · Run it\]** Save the file as firstclass dot py. In the terminal, type python, space, firstclass dot py. Asha 91, then Ravi 78.

**\[7 · Recap\]** Let us recap. One: Parallel lists only match by position, so they break easily. Two: A class is a blueprint for one type of thing. Three: An object is one real thing built from the class. Four: Each object keeps its own data. Pause the video, and say these ideas out loud, once, slowly.

### Bug of the Day

**Bug kind:** output · **Bug file:** sync.py

Wrong code (Ravi has Asha's marks now):

```python
names = ["Asha", "Ravi", "Meera"]
marks = [91, 78, 85]
names.sort(reverse=True)
for i in range(len(names)):
    print(names[i], marks[i])
```

Python output (it runs, but the answer is wrong):

```text
Ravi 91
Meera 78
Asha 85
```

Fixed code (each name travels with its marks):

```python
students = [("Asha", 91), ("Ravi", 78), ("Meera", 85)]
students.sort(reverse=True)
for name, mark in students:
    print(name, mark)
```

**Why:** Sorting one list moved the names but not the marks, so the pairs broke. Keeping each name and mark together in one bundle makes that impossible.

### Narration script

**\[1 · Title\]** Last time we bundled data in a class. Today we add actions, called methods, and meet self.

**\[2 · Blueprint and things\]** A class is a blueprint, and an object is one thing built from it. Inside a class, you write functions with def. These are called methods. Every method takes a first parameter, named self. Self means, this very object. When you call dog dot bark, Python passes the dog in as self for you. So you never type self when calling, but you always type it when defining. Think of a cookie cutter and cookies. Each cookie is separate, but all come from one cutter.

**\[3 · A class with a method\]** \[HL 1\] The blueprint is called Dog. \[HL 2\] A method, written with def, inside the class. It takes self, which means, this dog. \[HL 3\] It prints Woof. \[HL 5\] Dog with brackets builds one dog, tied to d1. \[HL 6\] And another, tied to d2. \[HL 7\] Call bark on the first dog. We write no argument, Python passes the dog as self. Woof. \[HL 8\] The second dog barks too. \[HL 9\] The type name is Dog. \[HL 10\] And d1 is d2 is False. Two separate objects.

**\[4 · Two names, two objects\]** Here is the picture. The name d1 is tied to one dog object. The name d2 is tied to another. They look the same, but they are two separate objects in memory. Both come from the same class, so both know how to bark. Changing one does not touch the other.

**\[5 · Methods that use self\]** \[HL 1\] A Counter class. \[HL 2\] A method named hit. \[HL 3\] It sets the count of this object to zero. Self dot count is data stored inside the object. \[HL 5\] A second method. \[HL 6\] It adds one to this object's count. \[HL 8\] Build a counter, tied to c. \[HL 9\] Set its count to zero. \[HL 10\] Add one. \[HL 11\] And again. \[HL 12\] Print two. \[HL 13\] A second counter. \[HL 14\] Reset. \[HL 15\] Its count is zero. The first counter is unchanged.

**\[6 · Run it\]** Save the file as counter dot py. In the terminal, type python, space, counter dot py. Woof twice, Dog, False. Then two, then zero.

**\[7 · Recap\]** Let us recap. One: A class is a blueprint. Dog builds an object. Two: Functions inside a class are called methods. Three: The first parameter of a method is self: this object. Four: Each object keeps its own data. Pause the video, and say these ideas out loud, once, slowly.

**\[8 · missing self\]** Bug of the Day. We forgot self in the definition. Calling d dot bark still passes the dog as the first argument. Python says, type error, bark takes zero positional arguments but one was given. The fix is simple. Put self as the first parameter of every method.

### Bug of the Day

**Bug kind:** error · **Bug file:** dog.py

Wrong code (bark has no self parameter):

```python
class Dog:
    def bark():
        print("Woof!")

d = Dog()
d.bark()
```

Python output (exactly as Python prints it):

```text
Traceback (most recent call last):
  File "dog.py", line 6, in <module>
    d.bark()
    ~~~~~~^^
TypeError: Dog.bark() takes 0 positional arguments but 1 was given
```

Fixed code (self added):

```python
class Dog:
    def bark(self):
        print("Woof!")

d = Dog()
d.bark()
```

**Why:** Python passes the object as the first argument when you call d.bark(), so the method must have a parameter ready to receive it.

### Narration script

**\[1 · Title\]** Setting attributes one by one is slow and error-prone. Today a special method sets them up for us.

**\[2 · The setup method\]** Python has a special method named init, with two underscores on each side. It runs automatically, the moment an object is created. Inside it, you store data on the object with self dot name equals name. The words after self are the arguments you pass when you build the object. Think of a form every new student fills in at the door. Nobody enters the class without name and marks. The values stored on the object are called attributes.

**\[3 · Setting up with __init__\]** \[HL 1\] The Student blueprint. \[HL 2\] The special method init. Self first, then the values we want. \[HL 3\] Store the name on this object. \[HL 4\] Store the marks on this object. \[HL 6\] Build a student with a name and marks. class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author
        self.borrowed = False

    def __repr__(self):
        return f"{self.title} by {self.author}"

class Library:
    def __init__(self):
        self.books = []

    def add(self, book):
        self.books.append(book)

    def borrow(self, title):
        for book in self.books:
            if book.title == title and not book.borrowed:
                book.borrowed = True
                return book
        return None

    def available(self):
        return [b for b in self.books if not b.borrowed]

### Bug of the Day

**Bug kind:** output · **Bug file:** shelf.py

Wrong code (the default list is created once and shared):

```python
class Library:
    def __init__(self, books=[]):
        self.books = books

    def add(self, title):
        self.books.append(title)

north = Library()
south = Library()
north.add("Python 101")
print(south.books)
```

Python output (it runs, but the answer is wrong):

```text
['Python 101']
```

Fixed code (None, then a fresh list per object):

```python
class Library:
    def __init__(self, books=None):
        self.books = [] if books is None else books

    def add(self, title):
        self.books.append(title)

north = Library()
south = Library()
north.add("Python 101")
print(south.books)
```

**Why:** A default value is built once, when the function is defined. A list as a default is therefore shared by every call. Use None, and build a fresh list inside.

### Bug of the Day

**Bug kind:** warn · **Bug file:** packets.cpp

Wrong code (packets never gets a value):

```cpp
#include <iostream>
using namespace std;

int main() {
    int packets;
    cout << "Packets: " << packets << endl;
    return 0;
}
```

Compiler output (a warning, the program still builds):

```text
packets.cpp: In function 'int main()':
packets.cpp:6:28: warning: 'packets' is used uninitialized [-Wuninitialized]
    6 |     cout << "Packets: " << packets << endl;
      |                            ^~~~~~~
packets.cpp:5:9: note: 'packets' was declared here
    5 |     int packets;
```

Fixed code (packets starts at zero):

```cpp
#include <iostream>
using namespace std;

int main() {
    int packets = 0;
    cout << "Packets: " << packets << endl;
    return 0;
}
```

**Fixed output:**

```text
Packets: 0
```

**Why:** A variable that you do not set holds whatever was in that memory before. Always write a starting value, such as zero.

### Bug of the Day

**Bug kind:** compile · **Bug file:** age.cpp

**Typed input:** (the terminal scene shows these characters, then Enter)

```text
17
```

Wrong code (cin uses the output arrows):

```cpp
#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";
    cin << age;
    cout << "Next year you will be " << age + 1 << endl;
    return 0;
}
```

Compiler output (exactly as g++ prints it):

```text
age.cpp: In function 'int main()':
age.cpp:7:9: error: no match for 'operator<<' (operand types are 'std::istream' {aka 'std::basic_istream<char>'} and 'int')
    7 |     cin << age;
      |     ~~~ ^~ ~~~
      |     |      |
      |     |      int
```

Fixed code (cin uses the input arrows):

```cpp
#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";
    cin >> age;
    cout << "Next year you will be " << age + 1 << endl;
    return 0;
}
```

**Fixed output:**

```text
Enter your age: Next year you will be 18
```

**Why:** The arrows for cin point right, toward the variable. The arrows for cout point left, toward the stream.

### Bug of the Day

**Bug kind:** output · **Bug file:** price.cpp

Wrong code (setprecision is used without fixed):

```cpp
#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    cout << setprecision(2) << 120.5 << endl;
    return 0;
}
```

Program output (it runs, but the answer is wrong):

```text
1.2e+02
```

Fixed code (fixed is added):

```cpp
#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    cout << fixed << setprecision(2) << 120.5 << endl;
    return 0;
}
```

**Fixed output:**

```text
120.50
```

**Why:** Without fixed, setprecision counts all digits, not only the decimals. Two digits is not enough for one hundred twenty, so cout uses a short scientific form.

### Narration script

**\[1 · Title\]** Programs become interesting when they can choose. Today we make our first real decisions with if and else.

**\[2 · Making decisions\]** A decision has three parts. The word if, a condition that is True or False, and a colon. The lines indented below run only when the condition is True. Else gives the other path, for when it is False. Think of a lifeguard flag. Red flag, you stay out. Green flag, you can swim. The program checks, then walks down exactly one path.

**\[3 · A two-path decision\]** \[HL 1\] The temperature is thirty four. \[HL 2\] The condition asks, is it greater than thirty? That is True. The colon opens the block. \[HL 3\] First line of the block, indented. \[HL 4\] Second line, same indent, so it is in the same block. \[HL 5\] Else covers the other path. Python skips it this time. \[HL 6\] This line would run if the answer were False. \[HL 7\] The last line is at the left edge, so it runs on both paths.

**\[4 · The path through the decision\]** Here is the decision as a map. Python arrives at the diamond and asks the question. If the answer is yes, it walks the if branch. If the answer is no, it walks the else branch. Then both branches join, and the program carries on with the next line. Exactly one branch is walked every time.

**\[5 · Pass or try again\]** \[HL 1\] \[TRACK marks=38\] Marks are thirty eight. \[HL 2\] Is marks greater than or equal to forty? No, thirty eight is smaller. \[HL 3\] So the Pass line is skipped. \[HL 4\] Python jumps to else. \[HL 5\] Try again prints. Change marks to forty, and Pass prints instead. Test the edge value, forty, every time you write a condition like this.

**\[6 · Run it\]** Save the file as marks dot py. In the terminal, type python, space, marks dot py. Try again. Thirty eight is below the pass mark of forty.

**\[7 · Recap\]** Let us recap. One: if runs a block only when its condition is True. Two: else runs when the condition is False. Three: The colon opens a block and the indent shows what belongs to it. Four: A line at the left edge runs whichever path was taken. Pause the video, and say these ideas out loud, once, slowly.

**\[8 · a missing colon\]** Bug of the Day. We forgot the colon after the condition. Python says, syntax error, expected a colon. The arrow points to the exact spot where the colon should be. ### Narration script

**\[1 · Title\]** Two paths are not always enough. Today we build a ladder of conditions, and learn why the order matters.

**\[2 · More than two paths\]** Sometimes there are many paths. Grade A, B, C and D. Python handles them with elif, short for else if. It checks the conditions from the top. The first one that is True wins, and Python skips the rest. Think of a ladder. You start at the top rung and step down until one rung holds. Because the first True wins, the order of the rungs matters a lot.

**\[3 · A grade ladder\]** \[HL 1\] Marks are seventy two. \[HL 2\] First rung. Is it ninety or more? No. \[HL 3\] So Grade A is skipped. \[HL 4\] Second rung. Seventy five or more? No, seventy two is smaller. \[HL 5\] Skipped. \[HL 6\] Third rung. Sixty or more? Yes. \[HL 7\] So Grade C prints. \[HL 8\] Python never looks at else. \[HL 9\] That last line is a safety net for everything below sixty.

**\[4 · Names and the chosen price\]** Look at the end state. Age is tied to the int sixty five. Price is tied to the int seventy. Only one of the four branches ran, and only that branch tied the name price to a value. If no branch had run, the name price would not exist at all. That is why we added a final else.

**\[5 · A ticket price ladder\]** \[HL 1\] \[TRACK age=65\] Age is sixty five. \[HL 2\] Under five? No. \[HL 4\] Under eighteen? No. \[HL 6\] Under sixty? No. \[HL 8\] Everything else lands in else, so the price is seventy, a senior discount. \[HL 10\] Print the chosen price. Notice that every branch ties the same name, price. That way the last line always has a price to print.

**\[6 · Run it\]** Save the file as ticket dot py. In the terminal, type python, space, ticket dot py. Ticket price, seventy.

**\[7 · Recap\]** Let us recap. One: elif adds more conditions after if. Two: Python checks from the top and runs only the first True branch. Three: Order matters: put the strictest condition first. Four: A final else catches everything that is left. Pause the video, and say these ideas out loud, once, slowly.

**\[8 · conditions in the wrong order\]** Bug of the Day. Marks are ninety five, a perfect grade A. But the program prints Grade C. Why? The first rung is, sixty or more. Ninety five passes it, and Python stops right there. The ninety test is never reached. Put the strictest condition first, and work down to the loosest.

**\[1 · Title\]** One condition is often not enough. Today we combine them, and meet the strange idea that a value can be false without being the word False.

**\[2 · Combining conditions\]** Three small words combine conditions. And is True only when both sides are True. Or is True when at least one side is True. Not flips the answer. Think of a beach club. To enter, you need a ticket and you need to be eighteen. A child or a senior citizen walks in free. Python also treats some values as false by themselves. Zero, an empty string, and None all count as False.

**\[3 · Combining two conditions\]** \[HL 1\] Age twenty. \[HL 2\] A ticket, which is True. \[HL 3\] Both sides must be True. Age is at least eighteen, and the ticket is True, so the line is True. \[HL 4\] Enter prints. \[HL 5\] Or needs only one side. Age below five? No. Age above sixty? No. Both are False, so the line is False. \[HL 6\] So Free is skipped. \[HL 7\] Not flips the ticket. True becomes False.

**\[4 · Truth table\]** Here is the truth table. And is True only in one row, when both are True. Or is False only in one row, when both are False. Not simply flips. Python also has a short list of values that count as False by themselves. Zero, an empty string, an empty list, and None. Almost everything else counts as True.

**\[5 · Truthiness\]** \[HL 1\] An empty string. \[HL 2\] An if with no comparison, just the name. Python asks, is this value truthy? An empty string is not. \[HL 3\] So Hello is skipped. \[HL 4\] Else runs. \[HL 5\] Name is empty prints. \[HL 6\] The bool function shows what Python thinks. Zero is False. One is True. The word Goa is True. An empty string is False.

**\[7 · Recap\]** Let us recap. One: and needs both sides True, or needs at least one. Two: not flips True and False. Three: Write each comparison in full on both sides of and or or. **\[8 · x equals one or two\]** Bug of the Day. Choice is three. We want to know if it is one or two. The program says Valid. Wrong! Python reads this as, choice equals one, or two. And the plain number two is always true. So the whole condition is always true. Write the comparison in full on both sides, choice equals one, or choice equals two, and it works.

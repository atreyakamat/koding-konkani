### Narration script

**\[1 · Title\]** Every for loop you have written secretly uses an iterator. Today we open the box.

**\[2 · One at a time\]** An iterable is anything you can loop over, such as a list or a string. The iter function turns it into an iterator, which hands out items one at a time. Each call to next gives the next item. When there are no more, Python raises a StopIteration, and the for loop quietly stops. Think of a ticket machine. Each press gives you the next ticket, until the roll is empty. And once the roll is empty, it stays empty.

**\[3 · A for loop by hand\]** \[HL 1\] A list of three numbers. \[HL 2\] The iter function gives us an iterator, tied to it. \[HL 3\] Next gives the first item. Ten. \[HL 4\] The second. A for loop does exactly this, and catches the StopIteration for you.

**\[4 · The list and its iterator\]** Here is the picture. The name nums is tied to the list. The name it is tied to a different object, a list iterator. The iterator does not copy the list. It points at it, and remembers how far it has walked. The list stays the same. Only the iterator moves forward.

**\[5 · Our own iterator\]** \[HL 1\] A Countdown class. \[HL 2\] Init remembers where to start. \[HL 5\] Dunder iter returns the iterator. File 2: countdown.py (scene 5)

```python
class Countdown:
    def __init__(self, start):
        self.n = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        value = self.n
        self.n -= 1
        return value

for i in Countdown(3):
    print(i)
print(list(Countdown(5)))
```

**Expected output:**

```text
3
2
1
[5, 4, 3, 2, 1]
```

### Narration script

**\[1 · Title\]** Writing a whole iterator class is long. A generator does the same job in a few lines.

**\[2 · Pause and resume\]** A generator is a function that uses yield instead of return. Calling it does not run the body. It gives back a generator object. Each time you ask for the next value, the function runs to the next yield. It hands the value out, and pauses. The next request resumes right after the yield. Nothing is stored in a big list, so a generator can even be endless. Think of a conveyor belt that makes the next cookie only when you reach for it.

**\[3 · A generator function\]** \[HL 1\] A function with yield. \[HL 2\] This print only runs when we first ask. \[HL 3\] Loop while n is above zero. \[HL 4\] Yield hands out n, and pauses here. \[HL 5\] When resumed, count down. \[HL 6\] After the loop, print done. \[HL 8\] Calling countdown runs nothing yet. We only get a generator object. \[HL 9\] Made it. Nothing has started. \[HL 10\] The first next runs the body. Start. Then yield three. \[HL 11\] The second next resumes after the yield. Two. \[HL 12\] A for loop takes the rest. \[HL 13\] One. Then done, and the loop ends.

**\[4 · Pause and resume\]** Here is the picture. A generator keeps a bookmark at the yield line. Each next call resumes from the bookmark. It runs to the next yield, hands out a value, and places the bookmark again. All local variables stay alive between calls. When the function ends, the bookmark is gone, and the generator raises StopIteration.

**\[5 · Lazy and endless\]** \[HL 1\] A generator that never ends. \[HL 2\] Start at one. \[HL 3\] Forever. \[HL 4\] Yield the number. \[HL 5\] Then add one. \[HL 7\] A second generator, built on the first. \[HL 8\] It pulls numbers one at a time. \[HL 9\] Past the limit, \[HL 10\] return, and the generator ends. \[HL 11\] Otherwise yield the square. \[HL 13\] The squares up to five. One, four, nine, sixteen, twenty five. \[HL 14\] The sum of squares up to ten. Three eighty five. The endless generator never filled memory, because values were made only when asked.

```python
def countdown(n):
```

File 2: squares.py (scene 5)

```python
def naturals():
    n = 1
    while True:
        yield n
        n += 1

def squares(limit):
    for n in naturals():
        if n > limit:
            return
        yield n * n

print(list(squares(5)))
print(sum(squares(10)))
```

**Expected output:**

```text
[1, 4, 9, 16, 25]
385
```

### Narration script

**\[1 · Title\]** A list comprehension builds everything at once. Swap the square brackets for round ones, and it becomes lazy.

**\[2 · Brackets decide\]** A generator expression looks like a list comprehension, but with round brackets. Instead of building the whole list, it makes values one at a time, as they are needed. import io
```python
import unittest

def add(a, b):
    return a + b

class TestAdd(unittest.TestCase):
    def test_small(self):
        self.assertEqual(add(2, 3), 5)

    def test_negative(self):
        self.assertEqual(add(-1, 1), 0)

    def test_text(self):
        self.assertEqual(add("a", "b"), "ab")

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestAdd)
result = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
print(result.testsRun, result.wasSuccessful())
```

### Bug of the Day

**Bug kind:** error · **Bug file:** floats.py

Wrong code (0.1 + 0.2 is 0.30000000000000004):

```python
assert 0.1 + 0.2 == 0.3
```

Python output (exactly as Python prints it):

```text
Traceback (most recent call last):
  File "floats.py", line 1, in <module>
    assert 0.1 + 0.2 == 0.3
           ^^^^^^^^^^^^^^^^
AssertionError
```

Fixed code (math.isclose allows a tiny difference):

```python
import math

assert math.isclose(0.1 + 0.2, 0.3)
print("ok")
```

**Why:** Computers store most decimals as tiny approximations, so equal-looking numbers may differ in the last digits. Compare floats with math.isclose, not with equals.

### Narration script

**\[1 · Title\]** Today we make our own type. A struct groups related data, like the fields on an ID card.

**\[2 · Structs\]** A struct groups related variables under one name. Each variable inside is a field. You define the struct once, and then you make as many variables of it as you like.

The dot operator reaches one field. Think of an ID card. It is one card, but it holds a name, a class and a number.

Until now, a student would need two separate variables, one for the name and one for the marks. If you have fifty students, you must keep a hundred variables in step. A struct solves this.

A struct is your own type. After you define it, you can use it like int or string. You can pass it to functions, store it in a vector, and copy it.

**\[3 · A student struct\]** \[HL 5\] The struct has a name for the new type. \[HL 6\] The first field is a string. \[HL 7\] The second field is an int. \[HL 8\] Do not forget the semicolon after the closing brace.

\[HL 11\] Here we make a variable of the new type. \[HL 12\] The dot reaches a field. We set the name. \[HL 13\] Then we set the marks.

\[HL 14\] We print both fields. \[HL 5\] The word struct starts the definition. Student is the name of the new type. \[HL 6\] Each field has a type and a name, as in an ordinary variable.

\[HL 8\] Do not forget the semicolon after the closing brace. \[HL 11\] Now we make a variable s of type Student. \[HL 12\] The dot reaches the name field, and we store Asha. \[HL 13\] The dot also reaches marks.

**\[4 · Fields in memory\]** Look at the struct in memory. It has two fields. The name sits first, and the marks come next. The compiler may add small gaps between fields, to keep them aligned.

Notice that the struct is only a plan. It uses no memory until you make a variable of it. Each variable gets its own set of fields, so two students never share one name.

**\[5 · A struct in a function\]** \[HL 10\] The function takes a const reference, as in episode twenty-five. No copy is made. \[HL 15\] Braces fill the fields in order. Asha gets the name, and ninety-one gets the marks.

\[HL 16\] Ravi has seventy-eight. \[HL 17\] We call show for each student. The output has two lines. \[HL 10\] The function takes a const reference, so there is no copy, and the function cannot change the student.

**\[8 · A missing semicolon after a struct\]** Bug of the Day. The struct has no semicolon after its closing brace. The compiler says expected semicolon after struct definition. A struct is a declaration, so it needs a semicolon.

This is one of the most common beginner errors. The struct definition looks like a block, but it is a declaration. A declaration needs the semicolon at its end. Without it, the compiler reads the next line as part of the struct.

The error message then points to a strange place. When the error looks odd, check the line above it.

**Bug kind:** compile · **Bug file:** student.cpp

Wrong code (the struct has no semicolon after its brace):


```text

      |  ^
      |  ;
```

```cpp

#include <string>
using namespace std;

struct Student {
    string name;
    int marks;
};

int main() {
    Student s;
    s.marks = 91;
    cout << s.marks << endl;
```

**Fixed output:**

```text
91
```

**Why:** A struct definition is a declaration, and every declaration ends with a semicolon. The compiler reads on and gets confused.

### Narration script

**\[1 · Title\]** Today we meet classes. A class bundles data and the functions that work on it, and it hides the data from the outside.

**\[2 · Classes and objects\]** A class is a blueprint. An object is one thing built from the blueprint. A class has data and member functions.

Data is private by default. Only the class itself can touch it. The public functions are the buttons that everyone may press. Think of a lift. You press a button, but you never touch the motor.

A struct and a class are nearly the same in C plus plus. The one difference is the default access. A struct is public by default, and a class is private.

By convention, we use a struct for plain data, and a class when the type has rules to protect. A good class hides its data, and it offers a few clear functions.

\[HL 16\] The count is two. \[HL 4\] The class is the blueprint. \[HL 5\] The count is private, so outside code cannot touch it. \[HL 7\] The word public opens the door for the functions below.

\[HL 8\] Increment adds one to the private count. \[HL 9\] The word const after the brackets promises that get does not change the object.

**\[4 · Public and private\]** The table shows the rule. Count is private, so outside code cannot touch it. Increment and get are public, so anyone may call them. This protects the data.

### Bug of the Day

**Bug kind:** compile · **Bug file:** counter.cpp

Wrong code (main reads a private member):

```cpp
#include <iostream>
using namespace std;

class Counter {
    int count_ = 0;

public:
    void increment() { count_++; }
};

int main() {
    Counter c;
    c.count_ = 5;
    cout << "done" << endl;
    return 0;
}
```

Compiler output (exactly as g++ prints it):

```text
counter.cpp: In function 'int main()':
counter.cpp:13:7: error: 'int Counter::count_' is private within this context
   13 |     c.count_ = 5;
      |       ^~~~~~
counter.cpp:5:9: note: declared private here
    5 |     int count_ = 0;
```

Fixed code (main uses the public function):

```cpp
#include <iostream>
using namespace std;

class Counter {
    int count_ = 0;

public:
    void increment() { count_++; }
};

int main() {
    Counter c;
    c.increment();
    cout << "done" << endl;
    return 0;
}
```

**Fixed output:**

```text
done
```

**Why:** Private data is only for the class. Outside code must use the public functions.

### Narration script

**\[1 · Title\]** Today we learn the right way to set up members. The colon list runs before the body, and some members need it.

**\[2 · Member initializer lists\]** A member initializer list sits after the constructor brackets. It starts with a colon. It builds each member directly, before the body runs.

Const members and reference members must use it. Members are always built in the order of their declaration, not in the order of your list. Think of a school bag. You pack in the order of the checklist on the door.

There is a difference between building a member and assigning to it. In the body of a constructor, the members are already built, and then you change them. In the initializer list, each member is built with the right value at once.

For a string, this saves work. For a const member, it is the only way.

**\[3 · An initializer list\]** \[HL 10\] The colon starts the initializer list. \[HL 10\] Each entry names a member, and gives it a value in round brackets. \[HL 11\] The body runs after the list. \[HL 17\] We make a book.

The list runs first, then the body prints Book made. \[HL 18\] Then show prints the title and the pages. \[HL 10\] The list sits between the brackets and the body. Title and pages each get their value in parentheses.

\[HL 11\] The body runs after the list. This message proves that all members are already built. \[HL 17\] The object gets its name and its page count in one step.

**\[4 · Order of events\]** Follow the order. First, the members are built. They get the values from the list.

Then the body runs. Only then is the object ready for use. Notice the order of events.

First all members are built, in the order of the declaration. Then the body runs. So the body is the place for extra work, not for setting values.

**\[5 · A const member\]** \[HL 5\] The id is const. It must never change. \[HL 9\] A const member can only get its value in the list. Setting it in the body is too late.

\[HL 14\] We make a ticket with id one hundred and one, and price fifty. \[HL 15\] The output shows both numbers. \[HL 5\] This member is const. After it is built, it can never change.

\[HL 9\] The list gives it its value, so there is no assignment. \[HL 14\] The ticket gets id one hundred and one, and price fifty.

The program prints one hundred one, then fifty. The id can never change after the ticket is made. That is the idea of const.

**\[7 · Recap\]** Let us recap.

One. The initializer list sits between the colon and the body. Two. It builds each member directly.

Three. Const and reference members must use the list. Four. Members are built in declaration order.

**\[8 · A list in the wrong order\]** Bug of the Day. The list names second before first. But members are always built in the order of the declaration.

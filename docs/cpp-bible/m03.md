### Narration script

**\[1 · Title\]** Today we stop repeating ourselves. A function is a named block of code that you can call whenever you want.

**\[2 · Functions\]** A function is a named block of code. You write it once, and you call it by name as often as you like. When the function ends, the program returns to the line after the call.

A function that gives nothing back has the type void. Think of a tea stall. There is one recipe, and it makes many cups.

Why do programmers write functions? A long program becomes hard to read. Functions cut it into small parts, and each part has a name. When you need the same job again, you call the name, and you do not copy the code.

Every program you have written has one function already. It is main. Now you learn to write your own.

**\[3 · Your first function\]** \[HL 4\] The word void means this function gives nothing back. Greet is the name. The empty brackets mean it takes nothing in. \[HL 5\] The body prints a line.

\[HL 9\] In main, we call greet by its name. The program jumps to the function. \[HL 10\] We call it a second time. The line prints twice, and we wrote it once.

\[HL 4\] Read the first line as a label. It says the type that comes back, the name, and the inputs. \[HL 5\] Everything between the braces is the body, and it runs only when someone calls the function. \[HL 9\] A call is the name with round brackets.

Do not forget the brackets, or the compiler reads the name as a plain word. If you change the message in the body, both calls change together.

**\[4 · The call and the return\]** Follow the path. Main reaches the call. The program jumps into greet.

Greet prints its line. Then control returns to main, to the line after the call. Notice the jump.

The program leaves main, runs the body, and comes back to the exact place where it left. It is like a bookmark. The computer remembers where to return, so you do not have to.

**\[5 · Declare first\]** \[HL 4\] This line is a declaration. It tells the compiler that tea exists, and it ends with a semicolon. \[HL 7\] Now main can call tea, even though the body comes later.

\[HL 11\] The full definition sits below main. Without the declaration, the compiler would not know the name tea at line seven. \[HL 4\] A declaration is only a promise.

It names the function, the inputs and the type, but it has no body. Large programs keep declarations at the top, or in a header file. \[HL 11\] The body can sit anywhere below, in the same file or in another file.

**\[6 · Run it\]** Save the file as order dot cpp. Compile it with g plus plus. Then run the program.

The program prints One cup of tea. Notice that the declaration prints nothing. Only the call in main makes the output.

**\[7 · Recap\]** Let us recap.

One. A function is a named block of code. Two. You call it by writing its name and brackets.

Three. Void means the function gives nothing back. Four. Declare a function before you call it.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · Calling a function before it exists\]** Bug of the Day. Main calls tea, but the function is written below main. The compiler says tea was not declared in this scope. It reads from top to bottom.

Add a declaration above main, or move the whole function above main. The compiler reads the file once, from the top. It has no memory of the lines below. So any name must appear before it is used.

You have two easy fixes. Move the function up, or write a short declaration above main.

### Bug of the Day

**Bug kind:** compile · **Bug file:** order.cpp

Wrong code (tea is called before the compiler knows it):

```cpp
#include <iostream>
using namespace std;

int main() {
    tea();
    return 0;
}

void tea() {
    cout << "One cup of tea" << endl;
}
```

Compiler output (exactly as g++ prints it):

```text
order.cpp: In function 'int main()':
order.cpp:5:5: error: 'tea' was not declared in this scope
    5 |     tea();
      |     ^~~
```

Fixed code (a declaration comes first):

```cpp
#include <iostream>
using namespace std;

void tea();

int main() {
    tea();
    return 0;
}

void tea() {
    cout << "One cup of tea" << endl;
}
```

**Fixed output:**

```text
One cup of tea
```

**Why:** The compiler reads the file from top to bottom. It must see a function name before the line that uses it.

### Narration script

**\[1 · Title\]** Today our functions take values in and send a value back. Now they can do real work.

**\[2 · Parameters and return values\]** Parameters are the inputs of a function. They sit inside the brackets, each with a type and a name. The return statement sends one value back to the caller.

The type before the function name says what kind of value comes back. Think of a juice machine. You put in fruit, and you get juice out.

Parameters and arguments are easy to mix up. Parameters are the names in the function line. Arguments are the real values in the call.

A function can return only one value. If you need more, you will learn other tools later. A good function does one job, and its name says what the job is.

**\[3 · An add function\]** \[HL 4\] The type int before the name means the function returns an int. A and b are the parameters. Each has its own type. \[HL 5\] Return sends the sum back to the caller.

\[HL 9\] The call passes four and nine. Those values are called arguments. \[TRACK total=13\] The returned thirteen goes into total. \[HL 10\] Then we print it.

\[HL 4\] The two parameters are like empty boxes. They get their values when the function is called. \[HL 5\] The return statement ends the function at once. Any line after it does not run.

\[HL 9\] The order of the arguments matters. The first argument goes to the first parameter. \[HL 10\] The variable total holds a copy of the answer, and we print it.

**\[4 · Values in, value out\]** The call passes four and nine. The function gets them as a and b. It adds them. Then return sends thirteen back, and total stores it.

Notice that the function never knows where its numbers come from. It only sees a and b. That is a big strength. You can call the same function with numbers from the keyboard, from a file or from a loop.

**\[5 · Return a decision\]** \[HL 5\] If a is bigger, the function returns a and ends at once. \[HL 8\] Otherwise it returns b. \[HL 12\] The first call gives twelve. \[HL 13\] The second call gives thirty.

A function can use the same code for any two numbers. \[HL 5\] This is an early return. The function stops as soon as it knows the answer. \[HL 8\] If the first test fails, the code reaches this line.

Every path through the function must end with a return. \[HL 12\] Now we can use the call right inside the cout line.

**\[6 · Run it\]** Save the file as bigger dot cpp. Compile it with g plus plus. Then run the program.

The program prints twelve and thirty on two lines. Check the two numbers by eye. The bigger one of seven and twelve is twelve, and of thirty and five is thirty.

**\[7 · Recap\]** Let us recap.

One. Parameters are the inputs of a function. Two. Return sends one value back.

Three. The type before the name is the return type. Four. A return statement ends the function at once.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · No return in a function\]** Bug of the Day. The function makes a sum, but it never returns it. The compiler warns that there is no return statement in a function returning non-void. The caller gets garbage.

Add return sum at the end. The compiler cannot always tell what you meant, but it can see a missing return. A function that says int must give back an int on every path. Read the warning, and look at the last line of the function.

### Bug of the Day

**Bug kind:** warn · **Bug file:** add.cpp

Wrong code (the function never returns a value):

```cpp
#include <iostream>
using namespace std;

int add(int a, int b) {
    int sum = a + b;
}

int main() {
    cout << add(4, 9) << endl;
    return 0;
}
```

Compiler output (a warning, the program still builds):

```text
add.cpp: In function 'int add(int, int)':
add.cpp:5:9: warning: unused variable 'sum' [-Wunused-variable]
    5 |     int sum = a + b;
      |         ^~~
```

Fixed code (return sends the sum back):

```cpp
#include <iostream>
using namespace std;

int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int main() {
    cout << add(4, 9) << endl;
    return 0;
}
```

**Fixed output:**

```text
13
```

**Why:** A function with a return type must return a value on every path. Without a return, the result is undefined.

### Narration script

**\[1 · Title\]** Today your program learns to decide. It tests a condition, and then it takes one of two paths.

**\[2 · if and else\]** An if statement tests a condition. If the condition is true, the body runs. If it is false, the body is skipped.

Add an else branch for the false case. Exactly one branch runs. Think of a fork in the road. A sign says which way to walk, and you never take both paths.

Every program you use makes decisions. A phone checks the password before it opens. A bank app checks your balance before it pays. All of this starts with a plain if.

The curly braces hold the body of each branch. Even for one line, write the braces. They stop many mistakes when you add a second line later.

**\[3 · Pass or fail\]** \[HL 5\] Marks is seventy-two. \[HL 6\] The if tests whether marks is at least thirty-five. The test sits inside round brackets. \[HL 7\] The test is true, so this line runs and prints Pass.

\[HL 8\] The else branch is skipped. \[HL 9\] It would print Fail, but only for a mark below thirty-five. \[HL 6\] The test must give true or false. Here, the comparison gives a bool, and that is exactly what if needs.

\[HL 7\] This line runs only when the test is true. Our marks are above thirty-five, so the program prints Pass. \[HL 8\] Notice that else has no test of its own. It means, in all other cases.

\[HL 9\] Change marks to thirty, and this line runs instead.

**\[4 · Two paths\]** Here is the decision as a tree. The test is at the top. If it is true, we follow the left path and print Pass. If it is false, we follow the right path and print Fail.

The program never follows both paths. Notice that only one path runs in each run of the program. The other path stays silent, and the computer does not even look at it. A tree like this is a good way to plan code before you type it.

**\[5 · Even or odd\]** \[HL 6\] Cin reads a number. \[HL 7\] An even number has remainder zero when we divide by two. \[HL 8\] That branch prints even. \[HL 9\] Seven has remainder one, so the else branch runs.

\[HL 10\] The program prints seven is odd. \[HL 7\] The remainder of a number divided by two tells us if the number is even. Every even number gives zero, and every odd number gives one. \[HL 10\] You can use this trick for any test on odd and even, such as seats in a bus.

**\[6 · Run it\]** Save the file as parity dot cpp. Compile it with g plus plus. Then run the program. Type seven and press Enter.

The program prints seven is odd. Try more numbers. Type ten, and then type zero. Zero is even, because the remainder is zero.

**\[7 · Recap\]** Let us recap.

One. An if statement tests a condition. Two. The body runs only when the test is true.

Three. Else runs when the test is false. Four. Always use braces, even for one line.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · A semicolon after the if\]** Bug of the Day. A semicolon sits after the if test. C plus plus reads it as an empty body. The block below then always runs.

With marks equal to twenty, the program would still print Pass. The compiler warns about an empty body. Remove the semicolon. This mistake is hard to see, because the code looks almost right.

The semicolon ends the if statement early. The braces then belong to nothing, and they run every time. So read every if line slowly, and look at the end of the line.

### Narration script

**\[1 · Title\]** Today we handle more than two cases. We build a grade calculator with an else if ladder.

**\[2 · else if ladders\]** An else if ladder checks tests from the top down. The first true test runs, and the rest are skipped. A final else catches all other cases.

The order matters. Put the strictest test first. Think of a ladder. You climb down from the top until you find a rung that fits.

Why a ladder, and not many separate ifs? With separate ifs, every test runs, and more than one message may print. With a ladder, the program stops at the first true test.

The final else is optional. But it is a good habit. It tells the reader what happens when nothing else fits.

**\[3 · A grade ladder\]** \[HL 5\] Marks is eighty-two. \[HL 6\] Is it at least ninety? No, so we move down. \[HL 8\] Is it at least seventy-five?

Yes. \[HL 9\] This branch prints Grade B. The ladder stops here. \[HL 10\] The tests below never run.

\[HL 12\] The last else would catch every mark below fifty. \[HL 6\] The strictest test goes first. A mark of ninety or more gets the top grade. \[HL 8\] We reach this test only if the first one was false.

So we already know that marks are below ninety. \[HL 10\] The same idea repeats. Each rung only needs the lower limit. \[HL 13\] If every test fails, the final else runs, and it prints Grade D.

**\[4 · Grade bands\]** This table shows the bands. Each test only needs the lower limit. The tests above it have already removed the higher marks. That is why order is so important.

Notice how the bands cover all numbers with no gap. Every mark from zero to one hundred lands in exactly one band. When you write a ladder, check the edges by hand. Test ninety, test eighty-nine, and test zero.

**\[5 · Ticket prices\]** \[HL 5\] The age is sixty-five. \[HL 7\] Under five is free. \[HL 9\] Under eighteen pays fifty. \[HL 11\] Under sixty pays one hundred.

\[HL 13\] Everyone else gets the senior price of sixty. \[TRACK price=60\] Sixty-five matches the else branch. \[HL 16\] The program prints the price. \[HL 6\] The price starts with no value, and one branch gives it a value.

Every branch must set the price, or the program prints garbage. \[HL 9\] Children from five to seventeen pay fifty. \[HL 13\] The final else covers all ages from sixty up. That is why we do not need a test there.

**\[6 · Run it\]** Save the file as ticket dot cpp. Compile it with g plus plus. Then run the program.

The program prints Price colon sixty. Try the age ten, and then the age four. Each age falls into a different band.

**\[7 · Recap\]** Let us recap.

One. An else if ladder checks tests from the top down. Two. The first true test runs, and the rest are skipped.

Three. Put the strictest test first. Four. A final else catches every other case.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · Tests in the wrong order\]** Bug of the Day. A student has eighty-two marks. The program prints Pass, not Distinction. The loose test is first, and eighty-two passes it.

The ladder stops there. Always put the strictest test first. Then the ladder works from the top down. Read the ladder like the computer does.

It checks from the top, and it stops at the first true test. A loose test at the top catches everything below it. So put the hardest test first, and the easiest test last.

### Narration script

**\[1 · Title\]** Today we build a menu with switch. It is a neat way to pick one action from many.

**\[2 · switch and case\]** A switch statement compares one value with many case labels. It jumps to the matching case. The break keyword ends that case.

The default case handles all other values. Without break, the program falls through into the next case. Think of a menu board. You say a number, and the kitchen makes that dish.

Use a switch when you compare one value with many fixed choices. The code is shorter than a long ladder, and it is easier to read. But a switch works only with whole numbers and characters. It cannot compare text or decimals.

The break keyword is the most important part. Without it, the program keeps running into the next case.

**\[3 · Name the day\]** \[HL 5\] Day is three. \[HL 6\] The switch looks at the value of day. \[HL 7\] Case one does not match. \[HL 8\] Case two does not match.

\[HL 9\] Case three matches, so the program prints Wednesday. Then break leaves the switch. \[HL 10\] The default case runs when no case matches. \[HL 6\] The switch looks at day only once.

Then it jumps straight to the right label. \[HL 9\] A match prints Wednesday. The break on the same line jumps out of the switch. \[HL 10\] The default case is last.

It has no break, because nothing follows it. Always write a default case. It tells the reader that you thought about the other values.

**\[4 · Jump to the case\]** The table shows how the switch picks a case. The value of day finds the matching row. If no row matches, the default row runs. Case labels must be whole numbers or characters, not text.

Notice that the table has one row for each label. The switch reads the value, finds its row, and runs the code from that row down to the first break. That last part is the key. Remember it when you see fall-through.

**\[5 · A character menu\]** \[HL 5\] The choice is the letter b. \[HL 7\] Two case labels can share one action. Here the letters a and A both add. \[HL 11\] Our letter b matches this case.

\[HL 13\] It prints Buy. \[HL 14\] Break then ends the switch. \[HL 15\] Default would handle any other letter. \[HL 7\] A case label with no code under it falls through on purpose.

### Narration script

**\[1 · Title\]** Today your program learns to repeat. A loop does the same job again and again, with no copy and paste.

**\[2 · while loops\]** A while loop repeats a block as long as its test is true. The test runs before every round. When the test is false, the loop ends.

You must change the loop variable inside the body. If you do not, the test stays true, and the loop never ends. Think of a ceiling fan. It keeps turning while the switch is on.

Loops save you from typing the same line again and again. If you must print one thousand lines, you write one loop. The computer does the repeating, and it never gets tired.

Every loop needs three things. A start value, a test, and a change. If one of the three is missing, the loop breaks.

**\[3 · A countdown\]** \[HL 5\] We start n at three. \[HL 6\] The loop tests whether n is greater than zero. \[HL 7\] It prints the value. \[HL 8\] Then n minus minus lowers n by one.

\[TRACK n=2\] Now n is two, and the loop tests again. When n reaches zero, the test is false. \[HL 10\] The program prints Liftoff. \[HL 5\] This is the start value.

Without it, the test has nothing to look at. \[HL 6\] The test runs first. If it is false at the start, the body never runs at all. \[HL 8\] This line is the change.

Remove it, and n stays three forever. The loop then never ends. \[HL 10\] After the loop, the program carries on with the next line.

**\[4 · Round by round\]** Here are the rounds. In round one, n is three and the test is true. In rounds two and three, the same happens.

In round four, n is zero. The test is false, so the loop ends. Three rounds ran.

Notice that the test runs four times, but the body runs only three times. The last test is the one that fails. This detail explains many off-by-one mistakes, so remember it.

**\[5 · A running total\]** \[HL 5\] The counter i starts at one. \[HL 6\] The sum starts at zero. \[HL 7\] The loop runs while i is at most five. \[HL 8\] Each round adds i to the sum.

\[TRACK sum=3\] After two rounds the sum is three. \[HL 9\] Then i goes up by one. \[HL 11\] At the end, the sum is fifteen. \[HL 8\] The plus-equals line adds the current value of i to the sum.

The sum grows by one, then two, then three, then four, then five. \[HL 9\] Without this line, the loop never ends, and the program hangs. If that happens, press control and C to stop it.

**\[2 · break and continue\]** Break leaves the loop at once. The program continues after the loop. Continue skips the rest of this round, and goes to the next round.

Both keywords work in while loops and for loops. Think of a school bus. Break means the bus stops for good. Continue means the bus skips one stop.

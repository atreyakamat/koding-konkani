### Narration script

**\[1 · Title\]** Dictionaries have a few methods that make life easier. Today we read safely, and walk through every pair.

**\[2 · Safe reads and loops\]** Four methods cover most dictionary work. Get reads a key, and gives a default if the key is missing, so no error. Items gives key and value pairs together. Keys gives the keys. Values gives the values. Think of walking along the price board. You can read the names, the prices, or both together. A for loop over a dictionary walks over its keys by default.

**\[3 · get, items, keys, values\]** \[HL 1\] A dictionary with two fish. \[HL 2\] Get with a key that exists gives its value, five hundred. \[HL 3\] Get with a missing key gives the default we choose. Zero. No error. \[HL 4\] Items gives each pair. We unpack them into fish and price. \[HL 5\] Print each pair. \[HL 6\] Keys gives the keys, and list turns them into a list. \[HL 7\] Values does the same for the values.

**\[4 · Views, not copies\]** Here is a useful detail. Prices is one dictionary object. The methods keys, values and items do not copy it. They give a live view of the same dictionary. We wrapped them in list to get a plain list to print. If you change the dictionary, the view changes too. That also explains the bug of the day.

**\[5 · Loop over values\]** \[HL 1\] A dictionary with three fish. \[HL 2\] A running total. \[HL 3\] Loop over the values only. \[HL 4\] Add each price to the total. \[HL 5\] Three hundred fifty, plus five hundred, plus one hundred twenty, makes nine hundred seventy. \[HL 6\] A plain for loop over a dictionary gives its keys. \[HL 7\] So this prints each fish name.

**\[6 · Run it\]** Save the file as total_price dot py. In the terminal, type python, space, total_price dot py. Total, nine hundred seventy. Then pomfret, prawns and mackerel.

**\[7 · Recap\]** Let us recap. One: get returns a default instead of raising a KeyError. Two: items gives key and value together, keys and values give one side. Three: A plain for loop over a dictionary walks over its keys. Four: Do not add or remove keys while looping over a dictionary. Pause the video, and say these ideas out loud, once, slowly.

**\[8 · changing a dictionary while looping\]** Bug of the Day. We add a new key while looping over the dictionary. Python says, runtime error, dictionary changed size during iteration. Python cannot walk a dictionary that keeps growing. Loop over a list of the keys instead. That list is a snapshot, so you are free to change the dictionary itself.

### Bug of the Day

**Bug kind:** error · **Bug file:** loopdict.py

Wrong code (a key is added inside the loop):

```python
prices = {"pomfret": 350, "prawns": 500}
for fish in prices:
    prices["crab"] = 450
```

Python output (exactly as Python prints it):

```text
Traceback (most recent call last):
  File "loopdict.py", line 2, in <module>
    for fish in prices:
                ^^^^^^
RuntimeError: dictionary changed size during iteration
```

Fixed code (loop over a list of the keys):

```python
prices = {"pomfret": 350, "prawns": 500}
for fish in list(prices):
    prices["crab"] = 450
print(prices)
```

**Why:** Adding or removing keys while looping changes the size of the dictionary being walked, so Python stops with a RuntimeError; loop over a list copy of the keys instead.

### Narration script

**\[1 · Title\]** Lists allow repeats, and dictionaries need keys. Today we meet the set, a bag of unique values.

**\[2 · A bag of unique values\]** A set holds unique values. Duplicates disappear. It has no order, so no index either. Think of a guest list. Each name appears once, and you can quickly ask, is this person on the list? Sets also do maths, like Venn diagrams. A bar gives everything in either set. An ampersand gives what is in both. A minus gives what is in the first but not the second.

**\[3 · Make a set\]** \[HL 1\] A set with three items, but pomfret appears twice. \[HL 2\] The length is two, because the duplicate vanished. \[HL 3\] Add puts a new item in. \[HL 4\] Sets have no order, so we use sorted to print them in a stable order. \[HL 5\] The word in asks, is prawns in the set? True, and sets answer very fast.

### Code shown

File 1: wordcount.py (scene 3)

**Typed input:** (the terminal scene shows these characters after the prompt, then Enter)

```text
The sea the sand The sun
```

```python
text = input("Text: ")
words = text.lower().split()
counts = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1
for word in sorted(counts):
    print(word, counts[word])
print("Most common:", max(counts, key=counts.get))
```

**Expected output:**

```text
Text: sand 1
sea 1
sun 1
the 3
Most common: the
```

### Bug of the Day

**Bug kind:** output · **Bug file:** wordcount.py

Wrong code (The and the are different strings):

```python
text = "The sea the sand"
counts = {}
for word in text.split():
    counts[word] = counts.get(word, 0) + 1
print(counts)
```

Python output (it runs, but the answer is wrong):

```text
{'The': 1, 'sea': 1, 'the': 1, 'sand': 1}
```

Fixed code (lower() before split()):

```python
text = "The sea the sand"
counts = {}
for word in text.lower().split():
    counts[word] = counts.get(word, 0) + 1
print(counts)
```

**Why:** Strings are case sensitive, so The and the are two different keys; make the text lowercase before you count.

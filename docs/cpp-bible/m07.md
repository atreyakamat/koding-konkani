### Bug of the Day

**Bug kind:** compile · **Bug file:** animals.cpp

Wrong code (the base member is private):

```cpp
#include <iostream>
#include <string>
using namespace std;

class Animal {
    string name_ = "Moti";

public:
    void eat() const { cout << name_ << " eats" << endl; }
};

class Dog : public Animal {
public:
    void fetch() const { cout << name_ << " fetches" << endl; }
};

int main() {
    Dog d;
    d.fetch();
    return 0;
}
```

Compiler output (exactly as g++ prints it):

```text
animals.cpp: In member function 'void Dog::fetch() const':
animals.cpp:14:34: error: 'std::string Animal::name_' is private within this context
   14 |     void fetch() const { cout << name_ << " fetches" << endl; }
      |                                  ^~~~~
animals.cpp:6:12: note: declared private here
    6 |     string name_ = "Moti";
```

Fixed code (the base offers a public function):

```cpp
#include <iostream>
#include <string>
using namespace std;

class Animal {
    string name_ = "Moti";

public:
    const string& name() const { return name_; }
};

class Dog : public Animal {
public:
    void fetch() const { cout << name() << " fetches" << endl; }
};

int main() {
    Dog d;
    d.fetch();
    return 0;
}
```

**Fixed output:**

```text
Moti fetches
```

**Why:** Private members belong to the base class only. A derived class cannot touch them. It must use a public or protected function.

### Narration script

**\[1 · Title\]** Today we learn who is built first. The order matters a lot when classes depend on each other.

**\[2 · Constructor and destructor order\]** When you make a derived object, the base part is built first. Then the derived part is built. When the object dies, the order reverses. The derived part goes first, and then the base part.

To give arguments to the base constructor, call it in the initializer list. Think of building a house. The foundation comes first, and the roof comes last. Taking it down reverses the order.

**\[3 · Build and destroy\]** \[HL 6\] The base constructor prints Base made. \[HL 12\] The derived constructor prints Derived made. \[HL 17\] Main makes one Derived object. The base part is built first.

Base made prints, and then Derived made. \[HL 18\] At the end, the order reverses. Derived gone prints first, and then Base gone.

**\[4 · Life of a Derived object\]** Follow the flow. The base is built first. Then the derived part.

At the end, the derived part is destroyed first. The base part is destroyed last. The derived part may depend on the base part, so the base must live longer.

**\[5 · Arguments for the base\]** \[HL 9\] The base constructor needs a name. \[HL 17\] The derived constructor takes a name and an age. \[HL 17\] In the initializer list, we call the base constructor first.

\[HL 17\] Then we set the age. \[HL 22\] Main passes both values. \[HL 23\] The output is Moti, three.

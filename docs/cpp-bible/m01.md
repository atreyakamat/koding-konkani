### Narration script

**\[1 · Title\]** Until now, our programs only printed words. Today they learn to remember things. You will make boxes for numbers, letters and yes or no answers.

**\[2 · Variables and types\]** A variable is a named box in memory. Every box has a type, and the type says what can go inside.

Int holds whole numbers, like three fish. Double holds numbers with a decimal point. Char holds one single character. Bool holds only true or false.

Think of a beach shack fridge. One shelf is for bottles, and one tray is for ice. Each place fits one job.

Why does C plus plus ask for a type at all? The type tells the compiler how much room the box needs. It also tells the compiler what the bits inside mean. The same bits can be a number or a letter, so the type decides.

A good name helps as much as a good type. Write fish count, not x. When you read the code next month, the name tells you the story.

**\[3 · Four variables\]** \[HL 5\] Int fish equals three. First comes the type, then the name, then the value. \[HL 6\] Double price equals one hundred twenty point five. \[HL 7\] Char grade equals A.

Notice the single quotes around the letter. \[HL 8\] Bool open now equals true. \[HL 9\] Now we print each one. The names have no quotes, so cout prints the value inside the box, not the name.

\[HL 5\] Read this line from left to right. The type is int, the name is fish, and the value is three. The equals sign here puts the value into the box. \[HL 7\] A char holds exactly one letter, so we use single quotes.

Double quotes are for whole words, and they mean a different type. \[HL 8\] Bool prints as one for true and zero for false, unless you ask for words. \[HL 12\] So the last line prints the number one on your screen.

**\[4 · Variables in memory\]** Here is what memory looks like. Each variable is a box with a name, a value and an address. An int takes four bytes on most computers. A double is bigger.

It takes eight bytes. A char takes one byte, and so does a bool. Different types have different sizes. Notice that two variables never share a box.

Each name has its own address. The address is where the box starts in memory. The computer reads exactly as many bytes as the type needs, and then it stops.

**\[5 · Sizes of types\]** \[HL 5\] The sizeof operator tells us how many bytes a type needs. \[HL 5\] For int, it prints four. \[HL 6\] A double needs eight bytes. \[HL 7\] A char needs one byte.

\[HL 8\] A bool needs one byte as well. These numbers match the boxes we saw before. \[HL 5\] The sizeof operator does not run any code at all. The compiler works out the answer while it builds the program.

The numbers four and eight are common, but the language does not promise them for every computer. Use sizeof when you need to be sure on your own machine.

**\[6 · Run it\]** Save the file as sizes dot cpp. Compile it with g plus plus. Then run the program.

Each line shows the size of one type. The numbers are four, eight, one and one. Your numbers may differ on another computer, but these four are normal on a modern laptop.

**\[7 · Recap\]** Let us recap.

One. A variable is a named box with a type. Two. Use int for whole numbers and double for decimals.

Three. Use char for one letter and bool for true or false. Four. Always give a variable a starting value.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · A variable with no starting value\]** Bug of the Day. Here we make an int called packets, but we never give it a value. The compiler warns us that packets is used uninitialized. The program still builds, but it prints a strange number.

That number is garbage left in memory. Give every variable a value when you make it. Garbage values are tricky, because the program may print zero on one run and a strange number on the next. That makes the bug hard to catch.

So make it a habit. Whenever you write a variable, write its first value in the same line.

**\[9 · Pun\]** An uninitialised variable walks into a bar. The bartender asks, what will you have? It says, whatever was there before.

### Bug of the Day

**Bug kind:** warn · **Bug file:** packets.cpp

Wrong code (packets never gets a value):

```cpp
#include <iostream>
using namespace std;

int main() {
    int packets;
    cout << "Packets: " << packets << endl;
    return 0;
}
```

Compiler output (a warning, the program still builds):

```text
packets.cpp: In function 'int main()':
packets.cpp:6:28: warning: 'packets' is used uninitialized [-Wuninitialized]
    6 |     cout << "Packets: " << packets << endl;
      |                            ^~~~~~~
packets.cpp:5:9: note: 'packets' was declared here
    5 |     int packets;
```

Fixed code (packets starts at zero):

```cpp
#include <iostream>
using namespace std;

int main() {
    int packets = 0;
    cout << "Packets: " << packets << endl;
    return 0;
}
```

**Fixed output:**

```text
Packets: 0
```

**Why:** A variable that you do not set holds whatever was in that memory before. Always write a starting value, such as zero.

### Narration script

**\[1 · Title\]** Today your program learns to listen. It asks a question, waits, and then uses your answer.

**\[2 · Reading input with cin\]** Cout sends data out to the screen. Cin brings data in from the keyboard. The arrows show the direction of the data.

For cout, the arrows point toward cout. For cin, they point toward the variable. Think of a ticket counter. The clerk asks where you go, and you answer.

Think about what the program does while it waits. It stops at the cin line and does nothing else. The keyboard fills a small buffer, and cin reads from that buffer when you press Enter.

Cin skips spaces and new lines before a number. That is why you can type the numbers on one line or on two lines. Both ways work the same.

**\[3 · Ask for an age\]** \[HL 5\] First we make an int called age. \[HL 6\] Then we print a question. There is no endl, so the cursor stays on the same line. \[HL 7\] Now cin reads a number from the keyboard and stores it in age.

The arrows point at the variable. \[HL 8\] Last, we print age plus one. The program waits at line seven until you press Enter. \[HL 5\] The variable age has no value yet, but cin gives it one on line seven, so this is safe.

\[HL 6\] A good program always tells the user what to type. Without the question, the user only sees a blinking cursor. \[HL 7\] If you type a word instead of a number, cin fails, and age gets no good value. We handle that later in the course.

\[HL 8\] The plus one happens first, and then cout prints the result.

**\[4 · Data flows through arrows\]** Follow the data. You type a number on the keyboard. The cin tool reads it.

The variable age stores it. Then cout prints a new number built from age. Notice that the flow goes in one direction only.

The keyboard sends characters, and cin turns them into a number. The number lands in the variable. After that, the variable is an ordinary box, and you can use it as often as you like.

**\[5 · Two numbers\]** \[HL 5\] We make two ints in one line. \[HL 7\] One cin line reads both numbers. Type them with a space between. \[TRACK a=4\] The first number goes into a.

\[TRACK b=9\] The second number goes into b. \[HL 8\] Then we print the sum, which is thirteen. \[HL 6\] The prompt says two numbers, so the user knows what to do. \[HL 7\] The arrows can chain.

Each pair of arrows reads one value, from left to right. Cin splits the input at the spaces, so one space, a tab or a new line all work.

**\[6 · Run it\]** Save the file as sum dot cpp. Compile it with g plus plus. Then run the program. Type four, a space, and nine.

Then press Enter. The program prints the sum. Try a few more pairs yourself. Type two large numbers, and check the sum with a calculator.

**\[7 · Recap\]** Let us recap.

One. Cout sends data out, and cin brings data in. Two. The arrows point in the direction of the data.

Three. Cin stores the typed value in a variable. Four. One cin line can read many values.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · The arrows point the wrong way\]** Bug of the Day. Here cin has arrows that point at cin. The compiler says no match for operator, with a long list. Do not panic.

The first line is the clue. Cin needs arrows that point at the variable. Change them, and the program builds. This error message is long, but the cause is short.

The compiler tries every version of the arrows it knows, and none fits. So it lists them all. Skip the list. Read only the first line, and look at the arrows in your own code.

### Bug of the Day

**Bug kind:** compile · **Bug file:** age.cpp

**Typed input:** (the terminal scene shows these characters, then Enter)

```text
17
```

Wrong code (cin uses the output arrows):

```cpp
#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";
    cin << age;
    cout << "Next year you will be " << age + 1 << endl;
    return 0;
}
```

Compiler output (exactly as g++ prints it):

```text
age.cpp: In function 'int main()':
age.cpp:7:9: error: no match for 'operator<<' (operand types are 'std::istream' {aka 'std::basic_istream<char>'} and 'int')
    7 |     cin << age;
      |     ~~~ ^~ ~~~
      |     |      |
      |     |      int
```

Fixed code (cin uses the input arrows):

```cpp
#include <iostream>
using namespace std;

int main() {
    int age;
    cout << "Enter your age: ";
    cin >> age;
    cout << "Next year you will be " << age + 1 << endl;
    return 0;
}
```

**Fixed output:**

```text
Enter your age: Next year you will be 18
```

**Why:** The arrows for cin point right, toward the variable. The arrows for cout point left, toward the stream.

### Narration script

**\[1 · Title\]** Today we mix types. Sometimes C plus plus changes a type for you. You must know when, and what is lost.

**\[2 · Type conversion and casting\]** C plus plus converts types when you mix them. An int becomes a double with no loss. A double becomes an int by cutting off the decimals. It does not round.

A cast is a clear request to convert. In modern C plus plus, we write static cast. Think of a jug and a small glass. Pour the jug into the glass, and some water is lost.

There are two kinds of conversion. The compiler does the first kind by itself, and we call it implicit. You ask for the second kind with a cast, and we call it explicit.

Explicit is better, because the reader can see your intent. A cast says, yes, I know data may change here.

**\[3 · Automatic conversion\]** \[HL 5\] Fish is an int with the value seven. \[HL 6\] We store it in a double. No loss happens. The weight is seven.

\[HL 7\] Price is nine point nine nine. \[HL 8\] We store it in an int. The compiler cuts the decimals. \[TRACK whole=9\] Whole is nine, not ten.

\[HL 9\] The first print shows seven. \[HL 10\] The second print shows nine. \[HL 6\] Seven becomes seven point zero. This conversion is safe, because every int fits inside a double.

\[HL 8\] This conversion is not safe. The decimals are cut off, not rounded. Nine point nine nine becomes nine, and the program stays quiet about it. \[HL 9\] The first print shows the double with no decimals, because it ends in zero.

**\[4 · Conversion rules\]** Look at the rules. Int to double is safe. Double to int cuts the decimals, so you lose data. Char to int gives the code of the letter.

Bool to int gives one for true and zero for false. Notice the direction of each arrow. A small box into a big box is safe. A big box into a small box can lose data.

Think of the jug and the glass again. Water poured from a glass into a jug is never lost.

**\[5 · static_cast\]** \[HL 5\] We have seven passed students out of eight. \[HL 6\] We cast passed to a double first. Then the division keeps the decimals. The answer is zero point eight seven five.

\[HL 8\] Here we cast the letter A to an int. \[HL 9\] It prints sixty-five. That is the code of the letter A. \[HL 6\] Read the cast first.

It turns a copy of passed into a double. The original variable does not change. After that, the double divided by an int gives a double. \[HL 9\] The letter A is stored as the number sixty-five.

Every letter has its own code number.

**\[8 · Casting too late\]** Bug of the Day. We cast the result of the division. The program prints zero. Why?

Seven divided by eight is zero in int maths. The cast comes too late. Put the cast on one number, before the division. Then the answer is zero point eight seven five.

### Narration script

**\[1 · Title\]** Today we learn three keywords. One saves typing, and two protect your values from mistakes.

**\[2 · auto, const and constexpr\]** The keyword auto tells the compiler to find the type from the value. The keyword const makes a variable read-only. You cannot change it after you set it.

The keyword constexpr is stronger. The value must be known when the program is compiled. Think of a sealed jar of masala. You can look at it, but you cannot change what is inside.

Why use const? It protects you from your own mistakes. If a value must never change, say so, and the compiler guards it for you.

Auto saves typing, but use it with care. When the type is obvious from the value, auto is fine. When the type is not clear, write it out.

**\[3 · Three keywords\]** \[HL 5\] Max seats is const. It stays forty for the whole program. \[HL 6\] Pi is constexpr. The compiler knows its value before the program runs.

\[HL 7\] Auto sees twenty-five point five and picks double. \[HL 8\] Auto sees twelve and picks int. \[HL 10\] The fare is a double times an int. The answer is three hundred and six.

\[HL 5\] A const variable must get its value in the same line. You cannot add the value later. \[HL 6\] Constexpr goes one step further. The compiler can use the value while it builds, for example to set the size of an array.

\[HL 7\] Auto looks at the right side of the equals sign. A number with a decimal point is a double. \[HL 8\] A plain whole number is an int. \[HL 10\] An int times a double gives a double, so the answer keeps its decimals.

**\[4 · Types and locks\]** Here is the memory. Max seats and pi are locked. The program cannot change them. Pi lives in the static region, because the compiler fixed it early.

The auto variables fare and seats look like ordinary boxes. The compiler picked their types for us. Notice the lock on two of the boxes. The program may read them as often as it likes.

But any line that tries to change them stops the build. Auto boxes have no lock. They are ordinary boxes whose type came from the compiler.

**\[5 · A const in use\]** \[HL 5\] Pi is a constexpr. \[HL 6\] The radius is const. We promise not to change it.

\[HL 7\] Auto picks double for the area, because pi and radius are doubles. \[HL 8\] The area is twelve point five six. \[HL 5\] Constants have names, and names tell the story.

A reader sees pi and knows what it means at once. \[HL 7\] Three variables go into one line, and auto still finds the right type. Here, every part of the formula is a double, so the area is a double.

**\[6 · Run it\]** Save the file as area dot cpp. Compile it with g plus plus. Then run the program.

The program prints the area, twelve point five six. Check the number by hand. Pi times two times two is about twelve point five six.

**\[7 · Recap\]** Let us recap.

One. Auto lets the compiler find the type. Two. Const makes a variable read-only.

Three. Constexpr needs a value known at compile time. Four. Use const for every value that should not change.

Pause the video. Say these ideas out loud, one time, slowly.

**\[8 · Changing a const\]** Bug of the Day. Max seats is const, but line six tries to change it. The compiler says assignment of read-only variable. That is a good error.

It stops a real bug before the program runs. Remove the line, or remove const if the value must change. Read the message slowly. It says read-only variable, and it names the variable and the line.

That is all you need. You can fix it in one of two ways. Remove the changing line, or ask yourself why the variable was const in the first place.

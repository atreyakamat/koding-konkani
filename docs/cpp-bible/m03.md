```cpp

    tea();
```



```text
One cup of tea
```

### Bug of the Day

**Bug kind:** warn · **Bug file:** add.cpp

Wrong code (the function never returns a value):

```cpp
#include <iostream>
using namespace std;

int add(int a, int b) {
    int sum = a + b;
}

int main() {
    cout << add(4, 9) << endl;
    return 0;
}
```

```text
add.cpp: In function 'int add(int, int)':
add.cpp:5:9: warning: unused variable 'sum' [-Wunused-variable]
    5 |     int sum = a + b;
      |         ^~~
```

Fixed code (return sends the sum back):

```cpp
#include <iostream>
using namespace std;

int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int main() {
    cout << add(4, 9) << endl;
    return 0;
}
```

**Fixed output:**

```text
13
```

**Why:** A function with a return type must return a value on every path. Without a return, the result is undefined.

### Narration script

**\[1 · Title\]** Today we meet a surprise. A function can change its input, and your variable still stays the same.

**\[2 · Pass by value\]** When you pass a value to a function, C plus plus makes a copy. The function works on the copy. The original variable never changes.

This is called pass by value. To send a result out, use return. Think of a photocopy. You can scribble on the copy, and the original stays clean.

**\[3 · A copy is changed\]** \[HL 10\] Number is ten. \[HL 11\] We call double it with number. C plus plus copies ten into the parameter n. \[HL 5\] The function doubles its copy.

\[HL 6\] Inside the function, n is twenty. \[HL 12\] Back in main, number is still ten. The copy was changed, not the original.

**\[4 · Two separate boxes\]** Look at the two boxes. Number lives in main. N lives in the function.

They have different addresses. The function doubled n to twenty. The box named number still holds ten.

**\[5 · A swap that fails\]** \[HL 4\] The function swaps a and b. \[HL 5\] It uses a helper box t. \[HL 12\] Main calls it with x and y. The function swaps only its copies.

\[HL 13\] So x is still one, and y is still two. We need another way to change the originals. That is the next episode.

**\[6 · Run it\]** Save the file as noswap dot cpp. Compile it with g plus plus. Then run the program. The program prints one and two. Nothing was swapped.

**\[7 · Recap\]** Let us recap.

One. Arguments are copied into the parameters. Two. A change to the copy does not reach the original.

```cpp
}
```

### Bug of the Day

**Bug kind:** warn · **Bug file:** calc.cpp

Wrong code (the default case has no return):

```cpp
#include <iostream>
using namespace std;

double calc(double a, char op, double b) {
    switch (op) {
        case '+': return a + b;
        case '-': return a - b;
    }
}

int main() {
    cout << calc(2, '+', 3) << endl;
    return 0;
}
```

Compiler output (a warning, the program still builds):

```text
calc.cpp: In function 'double calc(double, char, double)':
calc.cpp:9:1: warning: control reaches end of non-void function [-Wreturn-type]
    9 | }
      | ^
```

Fixed code (a final return covers every path):

```cpp
#include <iostream>
using namespace std;

double calc(double a, char op, double b) {
    switch (op) {
        case '+': return a + b;
        case '-': return a - b;
    }
    return 0;
}

int main() {
    cout << calc(2, '+', 3) << endl;
    return 0;
}
```

**Fixed output:**

```text
5
```

**Why:** If op is neither plus nor minus, the function reaches the end without a return. Every path must return a value.
